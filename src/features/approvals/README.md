# 审批

- 相邻工作区未提供可读取的 H5 审批页面，故不声称迁移某个旧页面；首期使用应用头部的受权限保护弹层，不新增服务端导航树外的侧栏项。
- 头部在 `approvals:read` 下按当前成员身份读取一次服务端授权的待办计数，仅接受非负安全整数，用作待办图标角标；零值或读取失败时隐藏，不轮询。待办分页仍只在用户主动打开时读取；任何审批写入成功后都通过 `approval-pending` 缓存前缀刷新列表与角标，不以本地身份猜测资格。
- 查询响应的后端契约已回显 version 和 `allowedActions`；待办列表只呈现窄投影，但可勾选服务端明确允许 `APPROVE` 或 `REJECT` 的事项，批量动作只消费同一条目的 capability 和 version。批量结果必须完整回显请求的所有事项且 `atomic=true`；任一项失败时不更新缓存，审批事实、业务对象与关联、申请人、参与者和时间戳均不进入缓存。
- 选中待办后可查看同一服务端可见审批的状态和步骤时间线，并仅在详情的 `allowedActions` 中出现时显示通过、驳回、转审、撤回或取消。每次写入提交同一详情的 version，成功结果必须回显同 ID 的安全投影；转审成员仅来自受当前实例约束的候选接口。浏览器绝不比较本地 actor 或任务受理人，任务 key、备注、模式、事实、附件和实例生命周期均不展示或缓存。
- `approvals:manage` 成员可从应用头部打开审批定义目录；它按需分页读取服务端授权的定义，并在缓存边界只保留定义 ID、名称、对象类型与状态。步骤、条件、成员与部门范围、重复规则、描述、版本和时间均立即丢弃；目录项只在重新读取严格匹配的服务端基线后才开放最小模板编辑或状态切换，复杂/已启用模板始终失败关闭。
- 同时具有 `approvals:manage` 和 `organization:read` 时，可由服务端成员目录创建初始停用的最小定义草稿，或编辑同一严格基线：仅提交名称、对象类型、选定审批成员、审批方式和选定的兜底管理员；固定为一次性单成员步骤及管理员兜底，不写入描述、发起人范围、部门、角色或条件。创建响应仍只保留目录投影并失效列表；复杂定义编辑和路由扩展保持关闭。
- 每个目录项可在 `approvals:manage` 下打开“管理状态”。弹层只重新读取同一 ID 的状态/version 基线，经过明确确认才发送 `ACTIVE`、`INACTIVE` 或 `DELETED` 与该 version；定义配置、成员范围、步骤与条件均不进入交互或缓存。服务端对引用、启用前提与并发继续裁决。
- 同时具备 `approvals:manage + organization:read` 时，目录可打开“编辑最小模板”。它仅接受初始停用、`ONCE`、无发起范围/条件/角色且恰好一个 `MEMBER` 步骤的完整服务端基线，才允许改名称、成员、任一/全员方式和兜底管理员；任何复杂或已启用定义均失败关闭，绝不部分回写。
- 客户、线索、联系人、产品、商机、合同、发票、回款、回款计划和回访详情都通过同一个按需“发起审批”入口：只读取当前详情中已服务端确认的对象 ID、该页面固定对象类型下的发起选项、定义/选择项专用候选人和路由预览；选择未变化且预览明确 `executable=true` 时才以浏览器安全幂等键提交。它不读取审批事实、申请人、路由代码或全局成员目录，也不根据本地 authority 推断当前成员可否发起；服务端对记录可见性、定义适用性、成员范围和幂等性重新裁决。
