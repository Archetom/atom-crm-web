# Work 任务功能边界

## 首个 Web 切片

`/work/tasks` 与 `/work/tasks/:taskId` 均要求 `work-tasks:read`，不新增服务端
navigation 尚未下发的侧栏菜单。列表只使用 URL 页码和每页数量调用生成的
`WorkTaskQueryRequest`；路径任务 ID 和分页参数都不是授权依据，服务端继续复核
任务读取权限与当前成员的参与者可见范围。

当前 OpenAPI 快照把成功响应标为泛型对象。浏览和详情运行时窄投影只接受任务 ID、非负 version、
非空标题和服务端计算的 `overdue`，再保留可选优先级、到期时间和状态。任务描述、创建人、
负责人、关注人、业务关联、重复任务来源、提醒、工作台投影版本及开始/完成/取消时间都会在
浏览解码边界丢弃，不进入浏览缓存、页面或日志。详情只用路径 ID 请求服务端资源并复用同一投影；
响应 ID 不等于路径时失败关闭。

详情在 `work-tasks:write` 下会对服务端明确回显 `TODO` 或 `IN_PROGRESS` 的任务提供开始、
退回待办和完成入口。每个动作只发送当前窄投影的任务 ID 与 version，不发送或读取任务结构、
成员、业务关联、提醒或生命周期时间；服务端重新确认当前成员是处理人、状态允许且 version
未过期。浏览器只把成功响应经同一窄投影写回详情，并失效同一身份的列表；409 不自动重试。

评论列表固定读取服务端分页的前 20 条，要求 `work-tasks:read`；每条只保留稳定评论/任务 ID、
version、内容和创建时间，评论人及更新时间会被丢弃。`work-tasks:write` 成员可发表非空纯文本
评论，请求只带用户输入内容；服务端重新确认参与者可见性。删除评论需要作者资格，而当前前端不
保留作者身份，因此保持关闭。

`/work/tasks/new` 是不在菜单中的内部创建路由，同时要求 `work-tasks:read`、
`work-tasks:write` 与 `organization:read`。处理人只能从服务端在职且可见的成员目录选择；提交
只包含修剪后的标题、选中的成员 ID、从同一目录明确选择的最多 50 位唯一关注人、明确填写的非空
描述、受限优先级和可选到期时间；未选择优先级时交由服务端默认。业务关联、附件、提醒、周期规则
和重复来源不会进入表单、请求或缓存。服务端继续重新确认创建人、处理人/关注人在职性和业务范围。

`/work/tasks/:taskId/edit` 是仅管理者可用的内部路由，同时要求 `work-tasks:read`、
`work-tasks:write` 与 `work-tasks:manage`。它以独立的身份隔离缓存读取同一任务的完整编辑基线，
但只保留 ID、version、开放状态、标题、描述、优先级和到期时间；创建人、处理人、关注人、关联、
来源、提醒和生命周期字段仍会丢弃。保存必须带回完整的标题、描述、优先级、到期时间和 version，
服务端重新确认管理权限、开放状态和并发，成功后只把窄投影写回详情。服务端也允许创建人管理任务，
但当前响应没有经审查的 `canManageStructure`/caller capability；浏览器不能用本地 actor ID 与创建人字段
自行推导资格，故创建人专用入口等待后端补充该能力。

任务详情还会向同时拥有 `work-tasks:read`、`work-tasks:write`、`work-tasks:manage` 与
`organization:read` 的管理者提供“重新分配处理人”。候选人只能来自服务端在职且可见的成员目录；
详情不读取当前处理人，因此不会把任一候选标记为当前人。提交只带选中的 actor ID 与详情窄投影
当前 version，成功响应仍收敛为窄投影并使列表和评论失效。服务端会重新确认管理资格、任务开放状态、
参与者可见性、候选在职性与并发。服务端同样允许创建人重新分配，但浏览器不会由本地身份和原始创建人
ID 推导资格，创建人专用入口继续等待经审查的 caller capability。

同一权限组合还可打开“管理关注人”。它以独立的身份隔离缓存重新读取同一资源的完整关注人替换基线，
但只保留 ID、version、开放状态和完整的唯一关注人 actor ID 列表；创建人、处理人、描述、关联、来源、
提醒和生命周期字段都会丢弃。浏览器仅显示 actor ID，候选成员仍只来自服务端在职且可见的成员目录，最多
保留 50 个且不允许重复。保存只提交完整去重后的 actor ID 列表与基线 version；成功响应重新收敛为窄投影并
失效列表和评论。服务端继续确认管理资格、开放状态、成员在职性和并发；创建人专用入口同样等待 caller capability。

开放任务详情会向 `work-tasks:write` 成员提供“清除业务关联”。确认前后均不读取、显示或缓存既有
关联；请求只带详情窄投影的 version，并有意省略 `businessObjectType` 与 `businessRecordId`，由服务端
清除任何已有关系并重新核验任务可见性、在职性、开放状态和并发。选择或替换关联仍保持关闭：当前契约支持
客户、联系人、线索、商机、合同、发票、回款和回款计划，但没有统一的服务端候选目录或经审查的跨实体写入
能力，浏览器不能根据本地权限、ID 或缓存自行拼接候选范围。

管理者可在开放任务详情确认“取消任务”。请求只带详情窄投影的 version，服务端重新确认管理资格、开放
状态和并发；成功响应收敛为 `CANCELLED` 窄投影并失效列表与评论。服务端也允许创建人取消，但浏览器不
比较本地 actor ID 和创建人 ID，创建人专用入口继续等待 caller capability。

管理者还可确认“删除任务”，但仅当窄投影状态为 `TODO` 时显示并只提交当前 version。服务端重新确认
管理资格、未开始、无评论、无附件历史与并发，成功后浏览器移除详情/评论缓存、失效列表并返回任务列表；
它不会从评论首页、路径或缓存推导删除资格。创建人专用入口仍等待 caller capability。

对窄投影明确为开放且具有到期时间的任务，管理者还能打开“管理任务提醒”。它调用专用提醒计划接口，
在独立身份隔离缓存中严格保留 task ID、version 和最多 8 条固定步骤（到期前/到期时/逾期后、合法分钟偏移、
处理人/创建人/关注人三种接收角色）；步骤 key、通知投影版本及任何任务详情字段都会丢弃。保存只提交完整步骤
与提醒基线 version，成功后失效任务详情和列表。浏览器不读取、显示或比较创建人、处理人、关注人名单、通知状态
或本地身份来推导资格；服务端仍重新核验管理资格、任务可见性、开放状态、到期时间和并发。创建人专用入口继续
等待 caller capability。

任务详情在同时具有 `work-tasks:read` 与 `files:read` 时提供“查看任务附件”弹层；额外具有
`work-tasks:write + files:write` 时显示为“管理任务附件”。它参考
移动端任务详情页的附件分区与附件列表交互，
但不继承旧 H5 的直接添加、删除、全量任务文件投影或裸资源链接。新接口以任务参与者可见性和独立文件权限共同裁决：
分页只保留已发布的文件 ID、version、名称和可选媒体类型，大小、上传人、时间、可用状态和其他字段在解码边界丢弃。
有写入权限的成员只能选择 PDF、PNG、JPG 或 JPEG；客户端固定将当前任务 ID 与 `work-task` 目标类型交给既有
受控流程，逐文件创建意图、以认证 `application/octet-stream` 上传内容并读取检查状态。检查中的文件不会出现在
下载列表；版本化撤回必须二次确认，服务端仍重验参与者可见性、目标写权限、意图/检查约束与 version。下载通过已认证
API 请求取得 Blob 后临时保存；预览、Range、附件详情、文件大小、上传人和时间继续保持关闭。上传意图、文件 ID 和
检查结果均不进入 URL 或持久化状态。

`/work/task-series` 是 `work-tasks:read` 守卫下的周期任务内部列表。H5 审计没有发现独立的周期任务页面，故只
参考移动端任务详情页的 Work 入口与移动端卡片
密度，不继承任何循环任务行为、成员投影或旧 API。列表只保留标题、状态、经严格校验的日历规则和服务端
`allowedActions`；创建人、处理人、关注人、描述、自动化游标、实例数量、blocker 与时间戳均立即丢弃。
`/work/task-series/new` 仍需要 `work-tasks:write + organization:read`。它只创建草稿，并可提交修剪后的标题、服务端目录中
选定的处理人、最多 50 位唯一关注人、明确填写的非空描述、受限优先级和完整日历规则；未选择优先级时由服务端默认。
处理人和关注人候选均只在用户操作时从同一受限成员目录读取；自动化状态、实例与未来提醒模板仍不会进入表单、请求或缓存。

当服务端列表明确下发 `UPDATE` 时，页面才允许进入 `/work/task-series/:seriesId/edit`。编辑路由独立读取同一
系列完整、版本化详情基线，保留标题、描述、优先级、处理人、关注人和完整日历规则；成员替换只从服务端可见目录选择，
目录不可用时保留服务端回显 ID 并仍可保存其他字段。完整 `PUT` 只建立于该基线与当前 version，成功后失效列表和
移除详情缓存。`ACTIVATE`、`PAUSE`、`STOP` 分别只由当前列表项同名 capability 显示；恢复不从状态或本地调度配置
猜测，服务端继续复核调度器、成员资格、规则和并发。`UPDATE` 也允许打开独立的未来提醒模板，模板读取与替换仍使用
其自己的 version，绝不复用列表 version。任一可读成员可独立分页查看实例事实，但只保留发生序号、实际到期时间与
已生成/已跳过状态，生成任务、成员、时区、批次、原因与时间戳均丢弃。

重复任务入口仍保持关闭；它需要独立的周期规则、未来实例和提醒模板基线，不能从本页缓存或当前身份推导。
