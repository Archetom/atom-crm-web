# OA

P6 的 OA 页面不复用旧 H5 的静态表单或本地审批逻辑。`/oa/forms` 只由后端菜单和 `oa-forms:read` 开放；表单定义的审批定义与字段只取 `/api/v1/oa/forms/configuration-options`，该接口已按当前管理者的字段写入权限和可满足的审批条件过滤。页面不会接受手输的内部审批定义 ID 或字段 code。列表只定位目标 ID；编辑、变更状态和删除均先读取单条详情，随后才使用服务端回显的字段、状态和 version。详情失败时只显示受控错误，不会把列表投影回填为操作基线。

OA 申请、公告和收件箱继续只消费各自的服务端分页与资源响应。申请表单的可用列表只提供选择项；选定后必经 `/available/{formId}` 重新读取，字段、审批选择、FILE 草稿 formVersion、路线预览和提交都只使用该单条详情。申请中的成员、部门和审批选择均使用对应表单/步骤受限的服务端关键词检索与滚动分页；FILE 多阶段输入必须等待草稿和上传状态，只有 `UPLOADED` 文件会进入预览或提交。不能以全局目录、本地身份或手工 ID 替代。

- `pages/oa-forms-page.tsx` 管理表单定义，仅使用服务端过滤的配置目录。
- `pages/oa-announcements-page.tsx` 在同一路由提供当前成员收件箱与受限公告管理；管理受众只来自公告专用候选分页，既有受众须带服务端 `displayName`，资源动作只来自详情 `allowedActions`。
- `pages/oa-requests-page.tsx` 呈现当前成员可见的申请及详情；提交界面使用表单作用域候选、服务端路线预览和 FILE 草稿，不得提供原始 ID 输入。
