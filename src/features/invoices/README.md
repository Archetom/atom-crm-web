# 发票功能边界

全局 `/crm/invoices` 桌面列表已对齐参考站的当前页批量操作：`invoices:assign + organization:read` 时可从服务端在职成员目录批量转移负责人，`invoices:issue` 时可批量重置已开票项目，`invoices:delete` 时可批量删除待开票项目。请求只包含服务端当前行的 `invoiceId + version`，混合状态选择会在对应操作上显示禁用原因；任何列表语义或身份变化都废弃选择。后端以独立、原子、版本化批量契约复核可见范围、成员、字段策略和状态，错误不会部分更新。

## 首个 Web 切片

客户详情在同时拥有 `invoices:read` 与 `customers:read` 时提供内部路由
`/crm/customers/:customerId/invoices`，不新增服务端 navigation 尚未下发的侧栏菜单。列表只使用路径客户 ID、URL 页码和每页数量调用生成的 `InvoiceQueryRequest`；服务端再次复核发票读取权限、客户字段未遮罩读取权限和客户可见性。

当前 OpenAPI 快照将分页成功响应标为泛型对象。运行时只保留稳定的发票 ID、version、customer ID、合同引用、申请/发票编号、类型、状态和日期，并要求每条回显路径客户。金额、税率、开票抬头、税号、银行账户、联系人、电话、收件地址、物流和备注都在解码边界丢弃；服务端已按字段策略回显的 `customFields` 仅能在 `fields:read` 下由当前 INVOICE 字段目录命名后展示，绝不补全、写回或据此推断权限。结构化 `fileFields` 只保留正 file ID、显示名、可选媒体类型/大小和字段 code，且只在 `invoices:read + customers:read + files:read` 下以认证下载重新由服务端裁决。

申请编号可进入同一客户上下文的 `/crm/customers/:customerId/invoices/:invoiceId`。详情只请求该发票，再以同一窄投影解码；回显客户 ID 缺失或不等于路径客户时失败关闭。`fields:read` 下，详情会按需读取 ACTIVE、非内置、非 FILE 的 INVOICE 字段目录，并仅展示同一响应中已由服务端裁剪的值；目录、值或权限缺失时保持空白，且不把它们作为编辑基线。额外具有 `files:read` 时，详情只为本次响应返回的 FILE 字段条目提供认证下载；它固定当前发票 ID、`invoice` target type 和字段 code/file ID，下载时仍由服务端重新复核。详情不提供全量编辑；仅在服务端同时回显申请日期和发票类型时，拥有 `invoices:write` 与 `contracts:read` 的成员可编辑这两个字段。PATCH 仅发送本次实际变更的非空日期/类型与 version；金额、开票抬头、税号、银行、联系人、收件信息、物流、备注、动态字段和附件不会预填或写入。其余更新仍需要安全的版本化写基线后才会注册入口。

跨客户 `/crm/invoices` 的申请编号与移动摘要使用正安全 `invoiceId` 打开同一详情 Drawer。Drawer 只按发票 ID 重新请求服务端详情，不从列表缓存推断客户关系；关闭、详情内返回或删除只移除该参数，并保留关键词、场景、筛选、排序、保存视图和分页。客户上下文直达路由继续要求详情 customer ID 与路径一致。

同时拥有 `invoices:assign` 与 `organization:read` 时，详情提供负责人选择器。候选只来自服务端返回的在职成员目录；前端只提交所选成员 ID 和当前 version，不能手输成员 ID、缓存成员或推断其可分配范围。合同窄投影不保留负责人 ID，因此页面也不会读取或显示原负责人；服务端复核发票 owner scope、`OWNER_ACTOR` 字段写权限、成员在职与可分配范围及并发。成功响应仍经发票窄投影解码，并只更新同一身份的详情和列表；409 不自动重试。

服务端回显状态为 `PENDING` 且拥有 `invoices:issue` 时，详情提供“登记开票结果”表单。浏览器仅提交用户在本次表单直接填写的发票号码、开票日期和可选物流单号，以及当前窄投影的 version；表单不会读取或预填详情、合同、缓存中的号码、日期、物流或其他资料。服务端重新校验写入范围、状态/发票号码/开票日期/物流字段写权限、当前 PENDING 状态与并发。成功响应仍经窄投影解码，只更新同一身份的详情和列表；409 不自动重试。

服务端回显状态为 `ISSUED` 且拥有 `invoices:issue` 时，详情提供明确确认的“重置开票结果”。请求只使用当前窄投影回显的发票 ID 和原始 version；服务端重新校验写入范围、相关字段写权限、当前 ISSUED 状态与并发。成功后前端失效同一身份的详情和列表并重新读取状态；浏览器不从本地状态、发票内容、物流、合同、缓存或 authority 推导重置资格，409 不自动重试。

## 发票申请

客户详情及发票列表中的 `/crm/customers/:customerId/invoices/new` 需要
`invoices:write`、`contracts:read` 与 `customers:read`。合同只能从同一客户的服务端可见合同查询中选择，不能手输 ID；请求只包含用户明确填写的正金额（两位小数）、申请日期、发票类型、个人或单位抬头，以及可选联系人、联系方式、寄送地址和备注。选择单位抬头时纳税人识别号必填，开户行、账号、开票地址和电话可选；选择个人抬头时这些单位字段不渲染且不会发送。仅同时拥有 `invoices:assign` 与 `organization:read` 时才显示负责人目录；候选只来自服务端可见在职成员，明确选择才发送 `ownerActorId`，未选择时由服务端默认当前成员。`fields:read` 下表单按当前身份的 `INVOICE` 字段目录提交活动、非内置的标量动态字段；USER/DEPARTMENT 仅使用 `organization:read` 下受限的成员或部门目录，FILE 仅绑定 `files:write` 下同一 `INVOICE` 私有草稿中确认 `UPLOADED` 的文件 ID。字段目录、必填候选或必填附件不可用时创建保持关闭，RELATION 不降级为自由文本或 ID。上述敏感值只保留在当前表单与本次受认证请求中，绝不写入 URL、查询缓存、持久化存储或日志；金额不在浏览器参与算术。审批人和流程仍不出现在表单。服务端继续复核合同/客户可见性、可开票金额、负责人范围与字段写权限；成功响应必须回显路径客户，拥有 `invoices:read` 时才失效列表并进入详情，否则只显示返回编号。详情的安全编辑/开具流程边界保持不变。

## 版本化删除

发票详情中的删除入口需要 `invoices:delete`，并经过明确确认。请求只携带当前详情窄投影的 ID 与原始 version；浏览器不根据本地 owner、合同、状态、缓存或发票内容推断删除范围、是否可恢复、附件状态或其他删除前提。服务端重新校验 owner scope、并发版本和附件/文件字段撤回；409 不会自动重试，成功后仅失效当前身份的发票列表并返回客户上下文。

## 移动端交互参考

交互参考范围为移动端客户开票入口和发票详情的信息分组。

Web 仅借鉴客户上下文、列表到详情的可达性和信息层级；不继承旧 Vue 状态缓存、旧 API、金额处理、开票资料编辑或敏感字段展示。新实现以认证后的生成 OpenAPI 客户端和服务端资源/字段授权为准。
