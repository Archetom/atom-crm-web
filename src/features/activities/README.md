# 跟进活动功能边界

## 移动端交互参考

借鉴旧 H5 详情内时间线的信息密度；不复用其 Vue 状态、全局选择桥接、旧活动类型映射、文件上传或关系写回逻辑。

## 新 API 差异

客户、线索、联系人、商机、合同、发票、回款和单条回款计划详情都会通过 `POST /api/v1/activities/query` 读取固定首页的最近 20 条时间线。请求使用生成的 `ActivityQueryRequest`，只带当前详情已服务端确认的 ID、对应固定 subject type 和页码；服务端同时复核 `activities:read` 与该对象的可见性。运行时窄投影只保留活动 ID、方式、目的、内容、发生时间和下次联系时间，不保留作者、version、关联对象、附件、动态字段或其他业务记录。

“写跟进”同时要求 `activities:read` 和 `activities:write`。弹窗先读取 `GET /api/v1/activities/options`，只接受服务端 `METHOD` 目录项，再用生成的 `ActivityCreateRequest` 提交当前详情对象的 ID、固定 subject type、方式、可选目的、内容与发生时间；不合成默认方式，也不提交关联对象、附件、下次联系时间、模板字段或动态字段。成功后只失效当前身份和当前对象的时间线。

线索、联系人、客户和商机的桌面列表在同时具有对应列表读取权限与 `activities:read + activities:write` 时允许选择当前页记录并执行“批量写跟进”。弹窗将用户明确选择的同一方式、可选目的、内容和发生时间展开为至多 100 条生成的 `ActivityCreateRequest`，固定为该列表的 object type；不发送 version、负责人、租户、关系、附件、下次联系时间、模板或动态字段。翻页、搜索、场景、排序、保存视图或临时筛选都会清空选择。`POST /api/v1/activities/batch` 的成功反馈来自原子写入结果；服务端仍为每条记录重审成员资格、写可见性、同租户和方式目录，任何一条失败都不部分创建。

当前成员具有同一读写 authority 时，时间线中服务端明确标为 `FOLLOW_UP` 的条目提供编辑和删除。每个操作先读取 `GET /api/v1/activities/{activityId}` 的完整服务端基线；编辑只允许更改方式、目的、内容和发生时间，提交原始 version、未改写的关系集合及原有下次联系时间，删除只提交当前 version。缺少完整关系基线时失败关闭；关系、下次联系时间、附件与方式/模板目录管理仍保持在独立流程。409 不会自动重试，用户必须显式刷新并决定保留或放弃草稿。
