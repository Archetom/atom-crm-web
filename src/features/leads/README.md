# 线索功能边界

## 移动端交互参考

借鉴线索列表的关键词搜索、分页与移动端紧凑信息卡片。没有复用 Vue/uni-app、下拉刷新、全局列表 mixin、旧权限字符串、`tel:` 调用、旧接口或其 DTO。

## 新 API 差异

`GET /api/v1/leads` 使用一基页码的 `LeadQueryRequest`，由服务端按 `leads:read`、字段访问和数据范围返回结果。前端将关键词与分页保存到 URL，只展示服务端许可的线索、客户与负责人引用；不推断客户名称、关联范围、动态字段、附件、地址、协作者或旧 H5 的最后跟进信息。

线索详情读取使用 `GET /api/v1/leads/{leadId}` 和身份隔离的 Query Key。列表名称、桌面“查看”和移动摘要标题以正安全整数 `leadId` 打开同一详情 Drawer；关闭或详情内返回只移除该列表参数，保留关键词、场景、排序、保存视图和分页，直接访问详情路由复用同一 Surface。参考移动端线索详情页的基础信息、标签分区和转换确认交互，但不继承其客户端操作权限、动态字段、附件 URL 或老接口字段；当前只展示服务端返回且可安全投影的基础字段和地址，排除动态字段与协作者。地址只展示精确服务端回显，不充当编辑基线或补造地区信息。

详情在 `leads:read + files:read` 下还会呈现当前响应回显的 FILE 字段附件。窄投影只保留合法字段 code、正 file ID、文件名与可选媒体类型/大小；下载固定当前线索 ID 和 `lead` target type，经认证 Blob 请求再次接受服务端的记录可见性、字段策略和文件状态复核。字段目录、列表、草稿或本地权限都不能补齐附件、猜测下载路径或提供上传/撤回入口。

详情在 `fields:read` 下会按当前身份的 LEAD 字段目录显示同一响应已裁剪、脱敏的 ACTIVE 非内置非 FILE 标量值。目录只提供字段标题、选项标签和安全 URL 格式，不能证明字段可读、未遮罩或可写；缺少回显值、目录失败、未知、停用、内置或 FILE 字段均不显示，也绝不作为编辑基线。

线索基础新建使用 `POST /api/v1/leads` 的生成请求契约，参考移动端线索创建页的基础填写布局，但不复用其全字段表单、旧权限或老接口。当前提交名称、职务、联系方式、网站、说明、下次联系时间和用户明确选择或输入的标签；现有标签候选仅在 `leads:read` 与 TAGS 字段未遮罩时从服务端目录读取。用户还可明确填写一条主地址；只有填写详细地址时才提交地址对象，地区、城市和邮编均为可选且不会由浏览器推断。在 `leads:assign + organization:read` 下还可从服务端可见在职成员目录明确选择负责人，未选时省略 `ownerActorId` 并由服务端默认当前成员。在 `customers:read` 下还可从同一身份的服务端可见客户目录选择关联客户；选择后必须重新读取精确详情，只有确认 ID 才发送 `customerId`，确认失败不会静默降级为未关联创建。`fields:read` 下，当前身份可见的 ACTIVE 非内置标量动态字段会按字段目录填写；USER/DEPARTMENT 仅使用 `organization:read` 下的受限成员或部门目录。FILE 字段仅在 `files:write` 下绑定同一 LEAD 私有草稿中已确认 `UPLOADED` 的文件 ID；必填字段目录、候选或附件无法安全完成时，创建失败关闭。上级和协作者仍保持独立流程，不会由浏览器猜测可选对象或写入其 ID。

线索基础编辑使用 `PUT /api/v1/leads/{leadId}`，参考同一移动端创建页的编辑布局，但只提交相对详情基线变化的基础字段和原始 version。服务端标记为 `CONVERTED` 的线索不会显示编辑入口；这不是授权或不可变性的替代判断，服务端仍会最终拒绝并发或不允许的修改。下次联系时间会从详情预填，只有用户修改才提交，清空时发送生成契约允许的显式 `null`；上级、协作者、地址、动态字段和附件同样保留为独立流程。

线索详情的关联客户选择器同时要求 `leads:write` 和 `customers:read`。候选只来自同一身份下受服务端数据范围裁剪的客户目录，设置或更换只发送所选客户 ID 与详情原始 version；已有关系的清除须二次确认，并只发送生成契约允许的 `customerId: null` 与原始 version。

详情标签卡片在已受 `leads:read` 保护的详情中仅向 `leads:write` 成员提供“管理标签”。打开编辑器后先读取 `GET /api/v1/leads/tags`；只有目录成功解码，才可把当前详情的服务端可见标签作为 `PUT /api/v1/leads/{leadId}/tags` 的完整替换草稿。保存携带原始 version，拒绝空白、超长与规范化重复标签；目录失败、遮罩、服务端字段策略、数据范围和并发都不会由浏览器猜测或绕过。

线索层级读取 `GET /api/v1/leads/{leadId}/hierarchy` 的窄投影，只展示服务端当前返回的可见上级与下级。设置上级使用 `PUT /api/v1/leads/{leadId}/parent`，候选集排除当前已知可见后代，清除与设置均带 version；浏览器只作辅助防护，循环、容量和字段写入规则仍由服务端决定。

线索状态使用 `PUT /api/v1/leads/{leadId}/state` 原子更新锁定和成交状态。仅当详情明确回显布尔 `locked` 与 `OPEN|WON` 成交状态时，`leads:write` 下才打开编辑；保存始终携带原始 version，字段访问、生命周期、范围和并发仍由服务端复核。

线索创建前查重使用 `POST /api/v1/leads/duplicate-check`，只发送名称和联系电话，并只消费服务端在当前可见范围内的布尔值。不会显示、保留或推断潜在重复线索，最终创建仍以服务端校验为准。

线索个人关注使用 `PUT /api/v1/leads/{leadId}/star`。这是当前成员的个人状态，不需要 `leads:write` 或线索 version；它只在服务端确认当前成员仍可见该线索后更新，前端不会预先修改或跨身份共享关注状态。

线索列表的独立查重使用 `POST /api/v1/leads/duplicate-check`，并要求当前成员具备 `leads:read`。弹窗只接受名称或联系电话并只消费服务端返回的布尔值；关闭后不改变列表 URL、筛选或缓存，也不显示、保留或推断潜在重复记录。

线索 CSV 导出使用受控 `POST /api/v1/leads/export/csv` Blob 下载，只在 `leads:export` 下显示。首期固定请求 `lead_name`，并仅透传当前关键词、场景映射后的负责人/下属负责人/关注/转化条件，以及已解析保存视图或当前内存临时条件；浏览器不读取、解析、缓存或持久化 CSV 内容，字段未遮罩访问和读/导出范围交集均由服务端再次复核。

线索协作者管理使用 `GET` 与 `PUT /api/v1/leads/{leadId}/collaborators`，参考同一 H5 详情页的成员协作入口，但以服务端完整清单替换而非本地增量更新。入口要求 `leads:assign`；`GET` 必须返回完整的 `{ version, collaborators, callerState }` 基线，前端仅用该基线 version 完整替换，绝不从详情或本地状态补齐。基线缺失、加载中或解码异常时，草稿操作和保存均失败关闭；候选仅使用 `organization:read` 下服务端可见成员目录。`leads:write` 下可经确认调用 `DELETE /api/v1/leads/{leadId}/collaborators/me?version=...` 退出协作，服务端复核实际身份，成功后清除详情/协作者缓存并返回列表。

线索负责人变更使用 `PUT /api/v1/leads/{leadId}/owner`，参考同一 H5 详情页的负责人选择交互。入口同时要求 `leads:assign` 与 `organization:read`，候选只取服务端可见成员，保存携带当前线索 version；成员活跃状态、可分配数据范围和字段写权限不由前端推断。

线索删除使用 `DELETE /api/v1/leads/{leadId}?version=...`，只在 `leads:delete` 下以二次确认发起。前端只提交当前详情 version，成功后清除线索域缓存并返回列表；不依据层级、转换状态或详情引用推断活动下级线索，也不处理附件或 FILE 绑定，均由服务端复核。

线索列表的当前页批量转移和删除分别使用 `PUT /api/v1/leads/batch/owner` 与 `POST /api/v1/leads/batch/delete`。前者仅在 `leads:assign + organization:read` 下展示受限在职成员目录，后者仅在 `leads:delete` 下经过二次确认；两者只提交当前投影的 `leadId + version`。关键词、分页、场景、排序、保存视图或临时筛选变更会清空选择，成功后失效线索查询；成员资格、可分配范围、字段策略、活动下级、附件/FILE 撤回和整批原子性全部由服务端复核。

线索转换使用 `POST /api/v1/leads/{leadId}/convert`，参考同一 H5 详情页的转换确认交互，但只在详情为 `ACTIVE` 且同时具备 `leads:convert`、`customers:write`、`contacts:write` 时显示。首期显式提交当前 version、客户名称、联系人名称和可选联系人职务；服务端原子创建后，前端只消费响应中与当前线索一致的客户/联系人 ID，并在已有相应 read authority 时提供跳转。客户和联系人自定义字段映射依赖独立字段访问上下文，不能从线索字段、本地缓存或旧 H5 映射规则推断，因此留待动态字段流程交付。

附近线索使用 `GET /api/v1/leads/nearby`，借鉴移动端线索列表的筛选后列表密度，但不复用旧地图、定位缓存、坐标上报、位置字段展示或接口。页面只在用户明确点击后请求浏览器定位，首期不接入地图供应商或 Key，而是按服务端距离分页；坐标不会进入 URL、持久化存储、日志或页面文本，半径、页码和每页数量才保存到 URL。响应只消费既有安全线索列表投影和服务端距离，地址与坐标继续留在服务端字段访问边界内。
