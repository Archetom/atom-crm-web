## 正式认证入口

`/login`、`/password-reset` 与 `/password-reset/confirm` 使用独立的公开认证壳，不加载内部应用的授权、导航或成员资料。桌面端左侧解释工作区登录、Cookie 会话、多工作区选择与一次性重置令牌；右侧表单是唯一的主要操作区。小屏幕隐藏说明区，保留完整标签、16px 输入文字、错误、加载和主操作，避免横向滚动。

登录第一步只采集由管理员或邀请邮件提供的“工作区 ID”、登录账号和密码；工作区 ID 不是全局目录入口，浏览器也不会通过账号反查、枚举或猜测工作区。验证成功立即清空密码，仅在当前页面内存保留短时 challenge，并以两步进度和可用原生 Radio 键盘操作的工作区卡片展示服务端返回成员资格。卡片显示工作区 ID 与已审查的来源/部门状态，不伪造租户名称、权限或成员范围。挑战已失效时回到第一步并提示重新验证。找回页维持不枚举账号的成功文案，设置页仅从当前链接读取一次性 token；任何错误都采用 `errCode` 的审查中文映射。

产品列表在 `products:export` 下提供“导出 CSV”确认弹窗。它固定导出产品名称、产品编码、单位和可用性，并只发送当前关键词、已确认分类、可用性场景、静态或当前字段目录确认的自定义排序，以及已解析保存视图或页面内存临时条件；不传页码、租户、成员、文件名或列表行。下载必须先通过认证请求得到受控 Blob，弹窗不展示、解析或缓存 CSV 内容；加载、权限或服务端上限失败时保留已审阅错误反馈。

`/crm/products/new` 在 `products:write` 下以真实创建请求提交名称、编码、目录价以及可选分类、单位和说明；上架状态使用明确的“上架/下架”选择，默认上架且只映射为服务端 `AVAILABLE|UNAVAILABLE`。分类只在同时具备 `products:read` 时从同一身份分类树展示为名称路径；加载时控件保持等待，失败时页面说明可创建未分类产品并提供重试，而不是显示或猜测分类。具备 `products:assign + organization:read` 时还显示可清空“负责人”，候选只来自同一身份服务端在职成员目录；只有明确选择才提交 `ownerActorId`，加载失败时保留未选并提示可由服务端默认当前成员。`fields:read` 下还按当前身份的 ACTIVE 非内置 PRODUCT 目录渲染动态字段：USER/DEPARTMENT 仅从 `organization:read` 的受限目录选择，FILE 仅绑定 `files:write` 下同一草稿中确认 `UPLOADED` 的服务端 ID；必填字段无法安全填写时关闭创建，RELATION 不伪造为文本或 ID。产品主图和详情图在 `files:write` 下各自上传至服务端私有草稿；页面显示检查中、通过或失败，并且只有全部已选图片通过检查才把同一草稿的精确 ID 随创建请求原子绑定，取消或清空会撤回草稿。成功后失效产品列表并只在具有读取权限时进入该服务端回显的详情；无读取权限时保留成功编号提示。产品详情在 `products:read + files:read` 下按主图/详情图分组认证读取和下载，在 `products:write + files:write` 下各自上传或版本化撤回，分组、排序、上限和检查状态不由浏览器猜测。

`/crm/products/:productId/edit` 先读取服务端完整安全编辑基线，加载、权限不足或字段缺失时不展示替换表单。基础字段随该基线 version 保存；`fields:read` 下的 PRODUCT 标量动态字段从空白开始，页面明确说明这是为了避免详情脱敏或只读值被回写。只有用户实际填写或清除的当前目录字段才会合并进入本次更新，未操作字段仍由服务端保留。人员和部门控件仍只使用 `organization:read` 下的受限目录，目录失败会保留基础字段保存能力并阻止自定义字段变更。FILE 只有同时具备 `products:read/write + fields:read + files:read/write` 时才开放：当前详情已服务端回显的同字段附件是唯一可保留基线；新文件先通过该产品 target-bound upload intent、认证内容上传与检查状态刷新，检查通过后才随明确触碰的 field code/file ID 顺序进入更新。移除既有附件只在保存后生效，未保存候选在移除或取消时会版本化撤回；详情加载、检查或撤回失败均关闭这一字段编辑，不把空列表、文件名、MIME、缓存或本地身份当作基线。RELATION 仍没有伪造入口。冲突时草稿锁定，用户必须明确放弃本地草稿后才能使用最新基线继续编辑。

产品详情在 `fields:read` 下还会以独立描述区呈现本次服务端已裁剪/脱敏的 ACTIVE 非内置非 FILE 自定义标量字段；字段目录只用于字段标题、选项和格式，未回显值或目录失败均不显示，不会构成编辑基线。它还会在 `products:read + files:read` 下以独立卡片呈现本次详情响应回显的 FILE 字段附件。卡片展示服务端字段 code、文件名、媒体类型和大小，下载按钮仅提交该响应的 code/file ID 与当前产品 ID，并以认证 Blob 请求再次接受服务端权限与字段可见性复核；响应没有字段标题时不从字段目录猜测中文名称，当前契约也不提供这些已绑定文件的上传或撤回入口。

客户与回访详情也会在 `fields:read` 下显示本次服务端已裁剪/脱敏的 ACTIVE 非内置非 FILE 自定义标量字段，并以同一独立卡片呈现 FILE 字段附件，分别需要 `customers:read + files:read` 与 `return-visits:read + files:read`。字段目录仅命名和格式化已回显的标量值，不推断字段权限或编辑性；每张文件卡片只显示服务端 code、文件名、媒体类型和大小，并用当前详情资源 ID、回显 code/file ID 发起认证 Blob 下载；无附件、无文件读取权限或任何无效回显都不显示替代入口，既不会从字段目录猜测标题，也不会伪造编辑、上传或撤回。

线索、联系人和商机详情也以同一独立卡片呈现当前服务端响应回显的 FILE 字段附件，分别需要 `leads:read + files:read`、`contacts:read + files:read` 与 `opportunities:read + files:read`。卡片只显示字段 code、文件名、媒体类型和大小，并以当前详情 ID、对应固定 target type 与回显 code/file ID 发起认证 Blob 下载；没有附件、没有文件读取权限或任何无效回显时不显示替代入口，字段目录、列表和草稿均不能补齐字段标题、路径或编辑/撤回能力。

线索、联系人、商机和合同详情在 `fields:read` 下也会以只读描述区显示本次服务端已裁剪/脱敏的 ACTIVE 非内置非 FILE 自定义标量字段。合同还要求原有的 `contracts:read + customers:read` 才读取字段目录。字段目录只用于字段标题、选项和安全 URL 格式，未回显值、未知/停用/内置/FILE 字段或目录失败均不显示，也不会成为编辑基线；加载和目录错误分别给出真实反馈。合同详情另在 `contracts:write + products:read` 下提供“管理合同产品”对话框：对话框打开才读取完整、版本化产品基线，加载/错误/空态均有真实反馈；每行都有带名称的数量与成交单价输入、移除动作，以及可键盘检索的受限可售产品候选。保存仅在完整基线加载完成且用户已形成草稿时可用；新产品单价可留空，折扣、行金额和合同总额不显示也不由客户端计算。

客户、线索、联系人、商机和产品的桌面列表在 `fields:read` 下共用当前成员的字段显示控制。控件只让用户隐藏或恢复该列表已安全投影的固定列，以及服务端字段目录中 ACTIVE、非内置、非 FILE 的自定义标量列；字段值（如有）、枚举标签与脱敏结果只使用同一列表响应，浏览器不补齐。变更会合并到服务端返回的完整布局（未知字段、固定、宽度和版本均保留）；更新成功会按服务端布局的排序重排表格，移动摘要卡不因桌面列偏好而丢失必要的上下文。

合同、回款、发票和回访在相应 `*:read` 下也提供跨客户全局列表，复用同一页头、关键词、分页、加载、空态和错误反馈；“我负责的”仅在 authorization 回显合法 actor ID 时可用，写入 URL 后只以既有 `ownerActorId` 交给服务端裁决；“下属负责的”写入同一 URL 场景并只发送 `subordinateOwnerOnly=true`，成员范围始终由服务端解析。`customers:read` 时，“筛选客户”可打开有标签、可键盘操作的受限客户目录对话框；选择只写入精确正 `customerId` 并回到第一页，刷新后从同一受限详情恢复客户名称。发票、回款和回访的“筛选合同”同样只在 `contracts:read + customers:read` 下显示，目录只显示合同名称或编号；选择或 URL 恢复均先用同一受限合同详情确认后才将 `contractId` 交给记录查询。回款的“筛选回款计划”只在 `receivable-plans:read + customers:read` 下显示，目录只显示服务端回显的期数；选择或 URL 恢复均先用同一受限计划详情确认后才将 `receivablePlanId` 交给记录查询，可与客户、合同筛选叠加。`fields:read` 时，工具区的字段设置使用当前成员的版本化对象布局，按服务端顺序隐藏或恢复编号、关系、日期、负责人和状态等已安全回显列；不会把动态字段、金额、税务、支付或收件信息带进桌面表格，移动摘要不受影响。合同另有服务端定义的生效/已作废状态，发票另有待开票/已开票状态；两者各自写入并从 `status` 恢复，手改 URL 中未发布或已删除的状态会被丢弃。合同提供固定的更新时间、创建时间、名称和负责人服务器排序；回款提供到账日、创建/更新时间、回款编号和负责人服务器排序；发票提供更新时间、创建时间、申请/开票日期、申请/发票号码和负责人服务器排序；回访提供回访时间、创建/更新时间、回访编号和负责人服务器排序。四者均将受限 `sort` 目录写入 URL，未知值退回各自默认值。合同全局列表的编号、名称和移动摘要写入正安全 `contractId`，从原列表上方打开同一详情 Drawer；Drawer 只读取服务端合同详情，关闭、删除或退出协作只移除该参数，关键词、场景、筛选、排序、保存视图和分页均保留。客户 ID 仅由服务端窄投影回显后显示；回款和发票可据此进入既有客户上下文详情，回访的客户关联被服务端隐藏时保持非链接文本。四类对象在相应 `*:write + customers:read` 下提供全局新建：客户通过有标签、可键盘操作的受限目录对话框选择；合同、回款、发票选择后转入已有客户上下文真实表单，回访日期必填、备注可选；关闭/取消恢复同一列表 query，全局新建菜单走相同路由。列表不显示金额、税务/收件资料、支付方式或动态字段，也没有未获契约支持的其余高级筛选或批量状态控件。

`/crm/marketing-activities` 以服务端导航和 `marketing-activities:read` 双重守卫展示活动名称搜索、关联对象下拉筛选、URL 分页、加载/空态/错误反馈及详情 Drawer；首屏请求每页 15 条，显式 URL `size` 仍按统一边界校验。名称和移动端“查看”以正安全 `activityId` 打开可恢复 Drawer，Drawer 不使用行缓存而是重新请求服务端详情，并在加载、错误和重试间给出明确反馈；关闭及删除只移除详情参数，不打断当前筛选或分页。新建态由明确的创建动作或 `create=1` URL 参数驱动，不能将其与未打开状态混淆。新建、编辑、删除按钮分别受 `marketing-activities:write` 与 `marketing-activities:delete` 守卫；表单包含名称、关联对象、员工/部门参与者、起止时间、类型、浏览数、提交数、预算、地址、简介和每用户一次开关。新建时可在“关联已有表单”与“创建采集表单”间选择：前者只在 `marketing-forms:read` 下读取与关联对象严格匹配的 `LEAD`/`CUSTOMER` 表单；后者只在关联对象为客户或线索且拥有 `marketing-forms:write` 时可用，字段选项、显示名称和必填事实均来自带 `targetObjectType` 的当前服务端字段目录，并明确提示保存将与活动一同创建一份目标匹配、未启用的表单。联系人场景关闭表单路径；编辑也只保留目标匹配的既有表单关联。关联表单若未启用，详情明确显示“尚未启用公开访问”，启用后才以服务端回显的公开标识呈现原生新窗口链接。浏览和提交计数仅接受浏览器可精确表示的非负整数，并由服务端以版本化持久字段回显；员工候选只能来自服务端在职成员目录，部门候选只能来自服务端目录且以原始部门 ID 持久化，浏览器不展开部门成员。可选预算、图片大小或表单关联缺失时都使用空态；即使服务端回显 `null` 也不允许格式化器进入错误边界。详情将活动图片分为 COVER 与 DETAIL 两组：每组最多 9 张 PNG/JPG/JPEG，上传经过受控意图、安全检查和发布状态，已发布文件才可认证下载或经确认撤回。字段逐项标签、占位符、帮助文案和排序的进一步调整继续在营销表单编辑器中完成；批量动作没有契约，因此保持关闭。

P6 的仪表盘和报表只使用服务端投影：工作台可读取并版本化保存当前成员的时间范围、日期区间和数据范围偏好；不可用指标不以零补齐。合同目标只读取概览中的当前成员 `ACTIVE_CONTRACT` 投影，浏览器不请求、合并或推导部门与租户目标；未配置和被收回的目标分别保持 `EMPTY` 与 `UNAVAILABLE`。`reports:read` 且服务端下发 `reports` 菜单时，`/reports` 展示核心指标、指标趋势、负责人排行和当前成员的自定义报表目录。趋势与排行的指标、日期区间和趋势粒度只接受已发布枚举与完整、有序日历日期；选择写入 `reportMetric`、`reportFrom`、`reportTo`、`reportGranularity`，非法或倒置范围整体安全回退为默认 30 天，浏览器不计算指标、聚合金额或推断任何数据范围。`reports:write` 才可创建、编辑或删除个人定义：首次目录可不带对象参数取得当前成员可读的服务端默认对象，时间字段、粒度、维度、指标、筛选字段/运算符/枚举值一律只从当次 catalog 选择；运行仅提交用户选定日期区间，并直接展示服务端列和行投影。OA 页面同样只在服务端下发 `oa.forms`、`oa.requests`、`oa.announcements` 菜单后进入，并使用各自的服务器分页响应。发起申请时，成员、部门及审批人都通过表单/选择步骤作用域的服务端关键词检索与滚动分页选择；浏览器先预览服务端审批路线，FILE 必须经草稿、上传意图与状态确认，只有 `UPLOADED` 文件可提交。`/oa/announcements` 将当前成员的收件箱与公告管理分栏：收件箱仅展示服务端投递的标题、正文、发布时间和已读事实，标记已读必须回显同一公告 ID；管理受众只能使用当前操作者的成员/部门候选分页，既有受众必须由详情回显名称后才允许完整回写。发布、定时、取消定时、撤回和删除均只在详情下发同名 `allowedActions` 时显示，并仅提交该详情 version；浏览器不从公告状态、创建人或本地 authority 推导资源动作。`/marketing/forms` 在 `marketing-forms:read` 下展示服务端分页表单、固定采集对象、公开链接、提交趋势与服务端可见目标记录关联；`marketing-forms:write` 才可从所有者作用域的目标字段目录创建、编辑、启停或删除。新建可选择客户或线索，目标一经创建即禁用修改；提交关联只按服务端回显的对象类型和记录 ID 呈现。公开 `/public/marketing-forms/:publicId` 使用无认证的独立 Provider，按服务端字段类型渲染；FILE 只适用于线索表单，依序走短期草稿、上传意图、二进制上传和 `UPLOADED` 状态确认，再以同一草稿和一次性幂等键提交。

营销表单“查看”只把服务端列表回显的正 ID 留在页面瞬态状态；Drawer 打开后重新读取单条详情，只有该详情回显的字段、公开标识、状态和 version 才可展示或作为编辑、启停、删除与趋势/提交关联的基线。加载或读取失败不回退使用列表行。

OA 表单桌面和移动列表均只留当前点击的 ID；编辑 Modal 先加载单条详情，状态变更和删除分别在重读当前状态/版本后的二次确认中执行。发起 OA 申请的可用表单下拉只显示选择项；选择后加载当前可提交详情，成功后才渲染动态字段、审批人候选与文件上传，加载中显示反馈，失败则禁用预览和提交且不使用列表缓存。OA 申请 Drawer 将当前详情回显的 FILE 字段按字段 code 分组显示；只有 `files:read` 才显示下载按钮，点击后以认证请求取得 Blob，失败以本地审阅错误提示反馈，不显示或复制受保护 URL。

P7 的 `/organization/tenants` 在服务端下发 `organization.tenants` 且当前成员具有 `organization:request` 时，展示服务端确认的可访问租户和可选部门 ID；页面不把该目录扩展为全局租户主数据管理。显式开发身份可点击“切换”，切换前须重新校验精确租户 `granted=true`，然后替换当前标签页开发会话并刷新；正式身份在登录页通过密码验证后选择服务端回显的可访问租户，由认证服务签发新会话，应用内不会伪造跨租户切换。租户页中的“部门管理”“成员管理”“用户管理”仅在相应路由实际存在于当前服务端导航，且当前有效 authority 仍匹配时显示；成员申请审批仍额外需要 `organization:write`。`/organization/departments` 以服务端返回的扁平部门目录构成仅供展示的树；根/子部门创建、重命名、移动、停用和删除只在 `organization:write` 下显示，均直接提交用户输入的名称或服务端目录中选择的上级 ID。前端仅排除当前树中自身/后代作为移动目标以减少无效操作，不把本地树当作完整性或循环校验依据。`/organization/members` 仅在 `organization:read` 下按 URL 关键词与分页显示当前成员可见的资料；关键词输入会同步显示历史导航或外部链接恢复的 URL 值，未提交草稿不因分页更新丢失。拥有 `organization:write` 的管理员可进入内部 `/organization/membership-requests` 审核当前租户的申请，且仅对服务端回显 `PENDING` 的项目明确通过或驳回。申请人可从租户访问页进入 `/organization/my-membership-requests`，在 `organization:request` 下提交、分页读取与撤回自己的服务端申请；目标租户 ID 必须由邀请或管理员明确提供，页面不会枚举目标组织、部门、成员或审核资格。

`/administration/users` 在 `users:read` 下使用具名 `UserPageResponse` 分页检索当前租户可见用户，用户名、邮箱、状态和页码保持在 URL。用户名和邮箱框会同步显示已恢复的 URL 条件，浏览器前进/后退或带条件进入不会造成“目录已经变更、输入仍是旧值”；尚未提交的输入不会被其他筛选或分页刷新覆盖，清空相应输入会移除该条件并回到第一页。`users:write` 才显示新建与状态切换，`users:delete` 才显示软删除确认；创建、状态更新和删除成功都会在页面给出明确反馈并刷新用户与当前身份下的成员目录。服务端在同一命令事务创建活动成员资料、当前租户成员资格和基础成员角色；停用、锁定、恢复和软删除同步成员访问状态。两个管理弹窗使用动作明确的中文“创建 / 保存状态 / 取消”按钮。创建表单的初始密码只在瞬态表单中使用，成功、关闭或取消后即清除，不会写入 Query 缓存、URL 或持久存储。状态值仅使用刷新后契约给出的 `ACTIVE`、`INACTIVE`、`LOCKED`，而不把删除状态伪装为可选项。

`/administration/roles` 只消费具名角色页、角色详情、分配页和能力目录。角色授权多选的 code 必须来自当次服务端 capability catalog；替换时仅保留当前角色同 code 的服务端 dataScope，不为新增 code 伪造范围值。角色名称、描述、`ACTIVE/INACTIVE` 状态、复制和删除都使用服务端返回的 version；系统角色只展示，不在浏览器提供写入入口。成员分配抽屉只展示 server 分页的 actor ID 与时间；新增候选只来自在职可见成员目录，缺少目录读取权限时不提供 actor ID 输入。

`/administration/fields` 在 `fields:read` 下提供服务端业务对象选择、响应式字段目录及当前成员布局抽屉。字段类型、角色策略访问级别和脱敏方式都直接使用生成契约枚举；自定义字段创建、编辑和停用仅在 `fields:write` 下出现，停用必须确认并携带服务端 version。布局编辑以完整服务端顺序、隐藏、固定和列宽集合为基线，新字段仅追加显示而不会覆盖原基线；首次保存省略服务端返回的 `null` version。角色字段策略只列出服务端角色目录中的启用非系统角色，读取需要 `fields:write + authorization:read`，保存还需要 `authorization:write + authorization:assign`，并始终回写完整字段策略及当前版本。

`/administration/embedded-pages` 在 `embedded-pages:read` 下以服务端对象、平台、状态目录提供筛选和响应式分页列表，筛选与页码保留在 URL。`embedded-pages:write` 才开放新建/编辑，写入使用当前响应的 version；停用页面才显示删除确认。客户详情的“嵌入页面”区域只请求服务器为 `CUSTOMER/{id}/WEB` 渲染好的 URL，不在前端替换 URL 模板，iframe 使用 `allow-forms allow-popups allow-scripts` sandbox（不含 `allow-same-origin`）和 `no-referrer`，不显示原始 URL。

`/crm/customers` 在 `saved-views:read` 下提供局部保存视图选择和高级筛选管理弹层，不增加侧栏项。缺省 URL 应用服务端默认视图，`savedView=all` 保持为明确“全部客户”，选择其他视图时以其 ID 写入 URL；客户列表和 CSV 导出都使用同一已解析视图。任何可读取保存视图的成员也可打开“临时应用筛选”：它使用相同的字段目录和键盘可操作 Modal，不创建或修改保存方案，应用时取消已选方案并提示临时条件数，清除或刷新后恢复常规列表。`saved-views:write` 才开放创建、编辑、删除和设默认。条件编辑器只列出服务端字段目录中 ACTIVE、searchable 且含 `filterOperators` 的字段，操作符以及 0、1、2 或 1–20 个值的边界都直接消费各操作符的 `minimumValueCount` / `maximumValueCount`，不在浏览器根据字段类型推断规则。`fields:read` 下同一工具区还提供当前成员的客户列表字段显示设置；它保留其他字段布局基线、仅覆盖本页管理的可见列，布局版本冲突不自动重试。

`/administration/connectors` 是头部“连接器”入口打开的内部控制面，不新增侧栏菜单。`connectors:read` 读取服务端分页、状态筛选与详情；`connectors:manage` 才显示创建、轮换、撤销、启停和退役确认。创建或轮换后以警告弹窗一次性展示完整凭证并允许用户主动复制，常规列表、详情和移动卡片只显示连接器引用、状态、key ID 与审计时间；`connector-ingress/probe` 没有浏览器 UI。

`/administration/enterprise-data` 由头部“企业数据”入口打开，不新增侧栏菜单。页面在 `enterprise-data:read` 下提供登记名称和精确身份查询，只展示具名 observation 的受治理字段。只有 observation 的服务端 `usageMode` 表示可采用时才呈现采纳入口；用户输入可见 Customer ID 和地址槽位键后，客户端先取 Customer 当前 version，再由服务端给出短期预览。确认页只允许勾选预览回显的事实，提交同一 preview reference、identity 与 version；预览过期或版本变化由服务端拒绝。

`/crm/leads/intake-clients` 在 `leads:intake-manage` 下展示服务器返回的无密钥客户端摘要，并从线索列表提供同权限的局部入口，不新增侧栏项。创建不需要浏览器填写 owner 或密钥参数；成功后仅在当前页面弹层展示一次 `{ client, apiKey }` 中的 `apiKey`，复制后由用户保存。关闭弹层或离开页面会清除该值，列表、停用响应和 Query 缓存只保留客户端 ID、keyId、owner、状态、版本和时间；启用客户端可经确认以返回的 version 停用。

P7 的应用头部“菜单设置”不新增侧栏项。它只显示 `GET /navigation/preferences` 返回的当前成员候选树，并可在 `navigation:write` 下调整同级顺序及隐藏状态；候选树已由服务端按当前 authority 过滤且未应用个人隐藏规则，故恢复隐藏项不需要、也不能借用管理目录。保存从完整 order/hidden 基线构造，保留当前响应中不再可展示的既有 code，并在成功后刷新启动导航。

P8 将移动数据视图调整为语义化列表而非已弃用的组件封装；桌面表格与移动卡片仍共享同一服务端分页结果。基础壳、用户列表、新建用户弹窗和客户公海目录均有自动化 WCAG A/AA 审计：筛选、分页大小和表单控件具备可访问名称，状态不只依赖颜色，密码显隐按钮保持至少 24px 的键盘/触控目标；1440px 和 1024px 使用完整服务端导航树验证侧栏宽度与无横向溢出，1280px 桌面验证跳过链接和弹窗，768px 平板验证客户公海，375px 移动导航可由键盘打开、Escape 关闭并将焦点还给触发按钮。

联系人工具区现提供“附近联系人”入口，进入独立的受控定位页。半径、页码与每页条数可由 URL 恢复；用户每次明确请求定位后才在当前页面内存中使用浏览器坐标，按服务端距离分页展示同一联系人窄投影。首次提示、定位拒绝/不可用/超时、列表加载与查询错误均有可见文字反馈，不显示坐标、地图或地址。

线索详情的“关联客户”与联系人采用相同的受控选择方式：仅在非已转换线索同时具备线索写入和客户读取权限时出现，候选取服务端可见客户目录；已有关系清除需要明确确认，且只提交当前详情 version 与生成契约允许的 `customerId: null`。

线索详情的“线索层级”读取服务端返回的受范围裁剪投影，并显示当前可见上级与下级；`leads:write` 下的“设置上级线索”采用服务端分页候选，排除当前线索与已返回的可见后代。清除和设置均携带详情 version，并保持标准 Modal 的标签、键盘焦点管理和提交中禁用反馈；循环、容量、字段访问和数据范围由服务端最终裁决。

应用头部“工具与设置”在 `organization:request` 下提供“更新我的资料”。弹窗使用真实受控表单输入显示名称、可选邮箱和 E.164 手机号码，提交中保留原操作并显示加载状态，成功在弹窗内明确反馈；关闭时清空本次资料与响应，不提供身份、租户或权限编辑。

商机列表的“销售管线管理”进入内部 `/crm/opportunities/pipelines`，不增加侧栏菜单。`opportunity-pipelines:read` 成员只读查看服务端管线/阶段目录；`opportunity-pipelines:manage` 才可新建初始停用条目、编辑名称/排序/阶段概率、启停或显式删除。所有编码在创建后为只读，确认框明确说明启用、停用和删除的服务端前置条件；每次操作携带服务端版本，冲突不会自动重试。

线索和联系人详情的“修改状态”均沿用受焦点管理的标准 Modal：只有服务端完整回显锁定与 `OPEN|WON` 成交状态才出现按钮，Switch 和具名成交状态选择器组成一次原子保存；提交中禁用关闭/保存，失败显示已审阅的本地提示，不把状态切换伪装为本地即时成功。

客户、线索、联系人、商机、合同、发票、回款和单条回款计划详情均增加受 `activities:read` 保护的跟进时间线：借鉴旧 H5 的详情内记录密度，但仅显示服务端返回的方式、目的、内容、发生时间与下次联系时间，不显示关系、附件、动态字段、作者或版本，也不创建未在导航树中的侧栏入口。

在同时具有 `activities:read` 与 `activities:write` 时，时间线标题区提供“写跟进”。弹窗从服务端方式目录选择方式，提交当前详情对象的方式、可选目的、内容、发生时间与可选下次联系时间；不继承旧 H5 的关系选择、附件上传或模板字段。

线索、联系人、客户和商机桌面列表在同一活动读写权限组合下提供当前页多选与“批量写跟进”。操作栏清楚显示已选数量；弹窗以标准具名控件收集同一方式、可选目的、内容和发生时间，并在提交中显示加载状态、阻止关闭。选择在任何列表上下文变化时清空，最多 100 条；成功以文本状态反馈实际批量数。移动摘要不伪造跨卡片选择，关系、附件、下次联系、动态字段、负责人、tenant 和 version 都不进入批量表单。

时间线中的服务端 `FOLLOW_UP` 条目在同一读写 authority 下提供编辑、删除；操作会先读取完整的服务端版本化基线，编辑保留完整关系并可改写或清空下次联系时间，冲突需要用户明确刷新。

客户、线索和联系人详情的标签卡片分别在对应 `*:write` authority 下提供“管理标签”。编辑器会先校验当前身份服务端返回的未遮罩标签目录，再以标签 chips 形式选择或输入最多 50 个标签；保存使用当前详情 version，不显示或回写遮罩标签。目录失败时编辑器保持不可保存，409 不会自动重试。

客户详情在 `return-visits:read` 下提供“查看回访”内部入口，借鉴旧 H5 的详情上下文，不增加侧栏菜单。列表、移动摘要和详情显示服务端返回的编号、回访时间、回访形式、客户满意度、客户反馈、关联 ID、负责人、记录状态和审批状态；详情额外显示时间戳。`return-visits:write` 下的客户上下文与全局“新建回访”使用同一真实表单：回访时间必填，回访形式、客户满意度、客户反馈、联系人和合同可选；全局创建的客户只能从 `customers:read` 的受限目录选择，不能手输 ID。创建时联系人选择器要求 `contacts:read + customers:read`，合同选择器要求 `contracts:read + customers:read`；二者只查询服务端当前客户候选，选择只提交用户明确选择的关联 ID。拥有 `return-visits:assign + organization:read` 时还显示可选“回访人”，候选只来自服务端在职成员目录；未选时明确由服务端默认当前成员。编辑页同样只编辑时间、回访形式、满意度和反馈，且只提交用户实际变更的选择值；清空回访形式或客户满意度会明确发送 `null`，未改字段保持省略。取消返回详情，409 显示保留草稿或放弃草稿并刷新两种选择。完整基线和 `VISIBLE`/`EMPTY` 关系状态下，详情关系选择器遵循相同读取权限；选择、更换携带原始 version，清除经确认且只提交对应关系的 `null`。拥有回访分配和组织读取权限时，详情还提供“变更负责人”对话框；`return-visits:delete` 成员还可在详情中经明确确认删除，成功后关闭详情并刷新列表。字段为空时保持未知，不补全联系人、合同或客户信息，也不进入附件或动态字段流程。

回访创建页在 `fields:read` 下按当前身份的 ACTIVE 非内置 RETURN_VISIT 目录补充动态字段：USER/DEPARTMENT 只从 `organization:read` 的受限目录选择，FILE 只绑定 `files:write` 下同一草稿已确认 `UPLOADED` 的服务端 ID。必填字段无法安全完成时关闭创建，RELATION 不提供自由文本或 ID 替代；详情与编辑仍不以创建时字段、附件作为更新基线。

回访详情在额外具备 `fields:read` 时提供“编辑自定义字段”弹窗。表单只使用当前身份服务端目录中的 ACTIVE、非内置标量定义，并从空白开始；用户明确填写或清除后，才以当前详情 version 合并发送对应 code，未操作字段绝不从详情回填或写回。由于生成的更新契约必须提交回访时间并会替换反馈，只有同一详情安全回显这两项基础值时才显示入口，保存会原样携带它们。USER/DEPARTMENT 仅从 `organization:read` 的受限目录选择；字段目录失败时禁用保存，FILE 和 RELATION 不显示伪造控件。保存成功刷新同一详情和列表，冲突与字段策略仍由服务端裁决。

同一回款详情在额外具备 `fields:read` 时也提供“编辑自定义字段”弹窗。表单只使用当前身份服务端目录中的 ACTIVE、非内置标量定义，并从空白开始；用户明确填写或清除后，才通过当前详情 version 合并发送对应 code，未操作字段绝不从详情回填或写回。USER/DEPARTMENT 仅从 `organization:read` 的受限目录选择；字段目录失败时禁用保存，候选目录失败时给出具名反馈，当前有效选择仍由服务端复核。FILE 和 RELATION 不显示伪造控件。保存成功刷新同一详情和列表，冲突与字段策略仍由服务端裁决。

客户详情在同时具备 `receivables:read` 和 `customers:read` 时提供“查看回款”内部入口。回款列表复用桌面表格、移动卡片和 URL 分页，回款编号在两种布局中都可进入同客户上下文的只读详情；列表和详情只显示回款编号、日期、合同/回款计划引用和状态。具有 `receivables:write`、`contracts:read` 与 `customers:read` 的成员还可进入“新建回款”：合同在弹层中按当前客户的服务端可见目录搜索和选择，表单采集到账日、回款金额、收款方式和可选备注；额外拥有 `receivable-plans:read` 时，可从所选合同的服务端可用计划目录选择一个关联计划。金额仅作为用户输入提交，不参与浏览器计算，计划目录中的金额也不展示或缓存；没有该读取权限则保持未关联回款。额外具有 `receivables:assign` 和 `organization:read` 时，表单还可从服务端在职成员目录选择负责人，只有明确选择才发送 `ownerActorId`，否则由服务端默认当前成员。备注仅随本次表单请求发送；`fields:read` 下还按当前身份的 ACTIVE 非内置 RECEIVABLE 目录渲染动态字段：USER/DEPARTMENT 仅由 `organization:read` 的受限目录选择，FILE 只绑定 `files:write` 下同一草稿已确认 `UPLOADED` 的服务端 ID；必填字段无法安全完成时关闭创建，RELATION 不提供自由文本或 ID 替代。详情未遮罩地回显回款日期时，同一写入/合同读取权限可在弹窗中编辑该日期；保存只提交实际变化的日期与 version，不读取或回写关联计划、金额、支付方式、备注、负责人、动态字段或附件。具有 `receivables:assign` 和 `organization:read` 的成员可从服务端在职成员目录变更负责人；具有 `receivables:delete` 的成员可在详情确认删除，确认框强调软删除和附件撤回，不展示或推断回款金额、合同或计划等删除前提。

客户详情在同时具备 `receivable-plans:read` 和 `customers:read` 时提供“查看回款计划”内部入口。回款计划列表复用桌面表格、移动卡片和 URL 分页，期数在两种布局中都可进入同客户上下文的只读详情；列表和详情只显示期数、到期日期、合同引用、进度和状态。具有 `receivable-plans:write`、`contracts:read` 与 `customers:read` 的成员还可进入“新建回款计划”：合同在弹层中按当前客户的服务端可见目录搜索和选择，表单只采集到期日、计划金额与收款方式。金额仅作为用户输入提交，不参与浏览器计算；计划、已收和剩余金额、提醒、备注、负责人、动态字段和附件均不展示或采集。详情未遮罩地回显到期日期时，同一写入/合同读取权限可在弹窗中编辑该日期；保存只提交实际变化的日期与 version，不读取或回写计划金额、支付方式、提醒、备注、负责人、动态字段或附件，已有回款历史的限制仍由服务端裁决。具有 `receivable-plans:delete` 和 `contracts:read` 的成员可在详情确认删除，确认框说明已有回款历史的计划会由服务端拒绝，并强调附件撤回；不展示或推断计划金额、进度或合同可见性等删除前提。

同一 `receivable-plans:write`、`contracts:read` 与 `customers:read` 权限组合还提供“批量新建回款计划”：从同一客户的服务端合同目录选择一个合同后，最多直接填写 100 条到期日、计划金额、收款方式、非负整数提醒、可选备注及 `fields:read` 下当前身份 ACTIVE 非内置 RECEIVABLE_PLAN 标量动态字段。USER/DEPARTMENT 候选只来自 `organization:read` 的受限目录；每行单独校验并在提交时绑定到对应草稿。浏览器不计算、汇总或分摊金额，也不采集负责人。批量生成契约没有文件草稿绑定，故不提供附件；若目录将 FILE 或 RELATION 标为必填，明确关闭批量提交并提示使用单条创建。

回款全局列表与详情还会展示服务端按当前字段权限回显的回款金额、收款方式、备注、负责人和审计时间；这些值不可作为全量编辑基线。回款和回访的桌面列表在 `fields:read` 下提供当前服务端字段目录中的动态列，并可从活动、非内置、可排序标量字段生成自定义排序。动态列和值均只来自同一服务端列表响应；隐藏、脱敏、停用或缺失的字段显示为空或不出现，浏览器不会补全，也不会对返回结果二次排序。回款详情在相同权限下会按需读取 RECEIVABLE 目录，并只将同一详情响应已回显的 ACTIVE、非内置、非 FILE 自定义值以目录标签呈现；它们不参与编辑、权限或范围判断。额外具有 `files:read` 时，发票、回款和回款计划详情都会将当前响应已回显的字段附件列为认证下载项；没有条目或缺少权限时不显示。

回款计划详情在额外具备 `fields:read` 时也提供“编辑自定义字段”弹窗。表单只使用当前身份服务端目录中的 ACTIVE、非内置标量定义，并从空白开始；用户明确填写或清除后，才通过当前详情 version 合并发送对应 code，未操作字段绝不从详情回填或写回。USER/DEPARTMENT 仅从 `organization:read` 的受限目录选择；字段目录失败时禁用保存，候选目录失败时给出具名反馈，当前有效选择与是否已有回款历史仍由服务端复核。FILE 和 RELATION 不显示伪造控件。保存成功刷新同一详情和列表，冲突与字段策略仍由服务端裁决。

回款详情中已展示的自定义字段值仍不参与编辑、权限或范围判断；可写入口是上文所述从空白开始的独立表单，只合并用户明确触碰的目录 code。回款计划详情中已展示的自定义字段值同样不参与编辑、权限或范围判断。

`worklist:read` 成员可从头部工具菜单打开“我的待办”。页面以日期选择器查看当天或指定日期的服务端聚合事项，只显示受控类别、摘要和到期时间；日期可恢复，加载更多 cursor 不显示或写入 URL。单项“确认”只提交当前服务端指纹，类别“确认全部”须二次确认并由服务端重新扫描；成功后该成员当前日期的待办刷新，原业务记录不被浏览器改写。

`work-tasks:read` 成员可直接访问 Work 任务内部列表与详情。列表复用桌面表格、移动卡片和 URL 分页，任务标题可进入详情；两个页面只显示标题、优先级、到期时间、状态、服务端计算的逾期标记，以及服务端明确回显的一条业务关联类型与记录 ID。任务描述、创建人、负责人、关注人、重复来源、提醒及开始/完成/取消记录不显示、不缓存。额外拥有 `work-tasks:write` 与 `organization:read` 的成员可由列表进入“新建任务”：填写标题、从服务端在职成员目录选定处理人和最多 50 位关注人，以及可选描述、优先级、到期时间和一组显式业务类型/记录 ID；类型与 ID 必须同时填写，关联仍由服务端重新确认。优先级未选择时由服务端默认；附件、提醒和周期规则不在新建请求中。开放任务详情的 `work-tasks:write` 成员可在 Modal 中输入同一受支持类型和正记录 ID 来关联或替换，或对已回显关联二次确认清除；输入不构成可见性证明，保存只携带当前 version 并等待服务端重判。额外拥有 `work-tasks:manage` 的成员可从开放任务详情进入“编辑任务”，此页只显示和完整回写标题、描述、优先级与可选到期时间；创建人、处理人、关注人、来源和提醒仍不显示或缓存，开放状态和 version 仅用于服务端并发校验。同一管理权限再加 `organization:read` 可打开“重新分配处理人”弹层，按姓名检索服务端在职成员并仅提交所选 actor ID 与当前 version；当前处理人不回显，弹层也不把候选标为当前人。“管理关注人”会独立读取完整关注人替换基线，只显示成员 ID，按姓名添加服务端候选并允许移除，最多 50 个且不能重复；保存完整列表和基线 version。拥有 `work-tasks:write` 时，服务端回显 `TODO` 的详情可开始或完成，`IN_PROGRESS` 的详情可退回待办或完成；页面只提交当前 version，处理人资格和状态转换继续由服务端裁决。详情显示服务端分页的前 20 条评论，只显示正文与创建时间；评论作者和更新时间不显示或缓存。具有写入权限的参与者可发表非空纯文本评论，删除评论保持关闭。

开放任务详情中的“关联业务记录”会显示服务端明确回显的类型与记录 ID。具有 `work-tasks:write` 的成员可在弹窗中明确输入一组受支持类型和正记录 ID 来建立或替换关联；输入不证明记录可见或可写，保存仅提交当前 version，并由服务端复核成员身份、任务开放状态、目标记录写入范围和并发。已有关联时，成员可经二次确认清除；清除请求仅携带当前 version 并省略类型与 ID。

具有 `work-tasks:manage` 的成员还可对开放任务确认“取消任务”。页面只提交当前 version，成功后显示服务端返回的 `CANCELLED` 状态；创建人权限和取消前提均不由浏览器推导。

同一管理权限可在 `TODO` 任务确认“删除任务”。页面不读取任务是否已有评论、附件或开始历史；只提交当前 version，服务端成功后返回列表，失败原因由经审查的错误码词条说明。

同一管理权限可对服务端窄投影为开放且具有到期时间的任务打开“管理任务提醒”。弹层独立加载完整提醒计划基线，只保留 task ID、version 和最多 8 条固定步骤；步骤只允许“到期前/到期时/逾期后”、合法分钟偏移及处理人/创建人/关注人接收角色。步骤 key、通知状态、创建人、处理人和关注人名单都不显示或缓存。保存提交完整步骤和基线 version，服务端复核管理资格、可见性、开放状态、到期时间与并发；浏览器不根据本地身份或任务成员推导创建人资格。

同一任务详情在额外具备 `files:read` 时提供“查看任务附件”弹层，参考移动端任务详情页的附件分区与列表密度；分页只显示服务端已发布附件的名称和可选媒体类型，以认证 fetch 下载为 Blob 后临时保存。额外具备 `work-tasks:write + files:write` 时入口显示为“管理任务附件”，可选择 PDF、PNG、JPG 或 JPEG：固定当前任务 ID 与 `work-task` 目标类型后，客户端逐文件创建受控意图、认证上传原始 `application/octet-stream` 内容并读取检查状态；检查未通过或尚未发布时不给出下载。已发布文件可用其服务端 version 经二次确认撤回。目标可见性、文件可用性、上传约束和并发始终由服务端复核；客户端不显示、缓存或伪造文件大小、上传人、时间、预览、Range、附件详情或旧 H5 的全量附件字段。

`/work/task-series` 参考同一 H5 Work 入口的列表/卡片信息密度；审计未发现旧 H5 的独立周期任务页，因此不继承旧循环逻辑。页面只显示服务端返回且通过规则一致性校验的标题、状态、频率、间隔、日历选择、时区、起止日期和时间；成员、描述、自动化游标、未来实例数量、blocker 和时间戳均不显示或缓存。可读成员可打开“查看实例”弹层，分页只显示发生序号、实际到期时间和已生成/已跳过状态；生成任务、成员、时区、批次、跳过原因和记录时间一律不显示或缓存。具备写入和成员目录读取权限时可创建草稿：表单采集标题、服务端处理人、最多 50 位关注人、可选描述、优先级、频率/间隔、星期或月日、IANA 时区、起止日期和本地时间；处理人和关注人候选只能来自服务端目录，优先级未选择时由服务端默认，不采集提醒。当当前列表项服务端下发 `UPDATE` 时，成员可进入 `/work/task-series/:seriesId/edit`，独立加载完整版本化基线并完整回写标题、描述、优先级、处理人、关注人和规则；成员候选只能来自服务端目录，目录不可用时保留服务端回显 ID。`ACTIVATE`、`PAUSE`、`STOP` 只在同名 capability 存在时分别显示恢复、暂停、停止确认，均仅发送当前 version。`UPDATE` 还打开未来提醒模板，模板以自身 version 完整替换固定步骤。浏览器不从创建人、管理角色、状态、本地调度配置或 actionBlockers 推断任一动作；服务端仍复核调度就绪、参与人、状态机和并发。

`notifications:read` 成员可从应用头部打开“通知设置”弹层，不增加服务端导航树外的侧栏项。弹层只呈现“接收邮件通知”和“接收 OA 公告邮件”两个布尔开关，并将完整的两个布尔值提交给当前成员偏好接口；邮箱地址、投递供应商、通道就绪状态、投递记录和更新时间一律不展示、不缓存，也不以开关状态承诺实际投递可用性。

同时具有 `notifications:read` 与 `work-tasks:read` 的成员可从头部铃铛打开“通知中心”。短列表只呈现服务端确认可见的 Work 通知标题、受限类型、优先级、到期时间和已读状态；不显示或缓存任务 ID、成员、提醒/投递投影、已读时间或创建时间，也不跳转任务详情。弹层打开期间每 60 秒刷新，关闭即停止；没有未读数端点时不实现全局角标轮询。未读通知可幂等“标为已读”，成功响应必须是同一 ID 的 `READ` 事实。

`approvals:read` 成员可从头部审计图标打开“审批待办”弹层；同一图标的角标只显示服务端确认当前成员可处理的非负数量，零值或读取失败时不显示，也不轮询。弹层仅在用户主动打开时分页读取服务端确认当前成员可见的 `PENDING` 事项，并只呈现可选标题和“待审批”状态；审批事实、业务对象/关联、申请人、参与者和时间戳不显示或缓存。列表允许批量勾选同时具有同一服务端 `APPROVE` 或 `REJECT` capability 的事项；提交各自 version 后，只有服务端回显完整的 `atomic=true` 成功结果才刷新待办和角标，失败结果明确显示为未执行且不会局部更新。选择一项后可查看同一服务端可见审批的受限实例状态，以及步骤名称、顺序、状态和处理时间；任务 key、处理人、备注、模式、附件和实例生命周期不显示或缓存。详情会根据服务端 `allowedActions` 显示通过、驳回、转审、撤回或取消，所有动作提交服务端给出的 version，成功结果必须回显同 ID 的安全投影；转审仅选择当前实例专用候选接口的成员，前端不比较本地 actor、申请人或任务处理人。`approvals:manage` 成员可从同一头部打开审批定义目录，仅显示定义名称、对象类型和启用状态；路由步骤、条件、成员/部门范围、重复规则、描述、版本和时间均不读取或缓存。额外具有 `organization:read` 时，目录提供“新建审批定义”，以及仅面向严格匹配停用单成员模板的“编辑最小模板”：编辑只能调整名称、成员、任一/全员方式和兜底管理员，复杂或已启用定义不显示配置也不回写。每个定义都有“管理状态”操作：它单独读取同一 ID 的状态/version，并经过确认启用、停用或删除；引用和激活前提继续由服务端裁决。目录在新建、编辑或状态子流程打开期间会退出，子流程关闭后恢复原来的目录查询状态，避免多层弹层遮挡成员选择。两者都不是导航树入口；复杂定义编辑仍未实现。客户、线索、联系人、产品、商机、合同、发票、回款、回款计划和回访详情均在服务端 authorization 明确含 `approvals:submit` 时提供按需“发起审批”；入口只传递页面固定对象类型和当前详情已确认 ID，定义、专用候选人与预览均须完整匹配该对象，预览未失效且 `executable=true` 才发送定义 ID、对象 ID、候选选择和一次浏览器幂等键；审批事实、路由代码和本地身份推断均不进入 UI。提交成功会立即刷新审批待办与当前对象的可发起定义。

服务端菜单下发 `workflow.definitions` → `/workflows` 且成员具有 `workflows:read` 时，可进入阶段工作流定义目录。目录只用 URL 页码与每页数量请求流程列表，并只呈现流程名称和业务对象；流程状态、阶段、字段、任务、审批门、适用成员/部门、条件、时间和资源级 `allowedActions` 都不显示、不缓存。额外具有 `workflows:manage` 时，目录提供“新建停用流程”：业务对象、必填字段和审批定义只从服务端配置目录选择，成员/部门仅使用专用候选分页，阶段/任务 code 与名称由成员显式输入。流程详情另提供配置管理：只有服务端返回 `UPDATE + version` 且全部阶段 `editable` 时才可完整替换；启用、停用或删除按钮只来自同一资源的 `CHANGE_STATUS + allowedStatuses + version`。客户详情的“启动阶段工作流”只请求同一客户的服务端适用项，`canStart=true` 才显示启动；成功后跳转受 `workflows:read` 守卫的 `/workflow-records/:workflowRecordId`，该页仅显示状态、当前阶段/任务摘要与审批门提示。记录 `ADVANCE` capability、version 和完整受限写入基线成立时，页面提供二次确认推进：未遮罩的文本、选择、日期时间、数字、布尔、邮箱、电话和 URL 字段只显示服务端名称、类型、值域和当前值；USER、DEPARTMENT、RELATION 只从当前运行记录 + field code 的候选分页显示类型匹配项；ADDRESS 只显示服务端下发的结构化分量及当前值。当前允许完成的任务仅显示名称与必填标记，成员显式勾选后才提交相应 `completedTaskCodes`，全部必填任务必须选择。没有审批人选择时仅提交 version，有选择时每项候选都从当前运行记录 + selection code 的服务端分页读取，选中后才提交相应 `selectedApprovers + version`。只有服务端恰好下发一个 `FILE_DRAFT` 字段时，用户选择的文件才会依次取得同一记录/字段的草稿、上传 intent、上传状态；页面仅临时显示用户刚选择的文件名、大小和状态，且只有 `UPLOADED` file ID 与同一 draft ID 才会提交。多 FILE 字段、未确认文件、FILE/ADDRESS/候选字段任一不完整基线会使整个字段推进保持关闭，绝不部分提交。仅当同一记录下发 `FAIL + version + allowedOutcomes` 时，页面提供“结束为未完成”：结果只从服务端标签选择，备注只按该结果的必填与最大长度填写。运行记录的评论区仅保留服务端返回的评论内容、可选创建时间、version 和逐条 `canDelete`；不显示评论人或更新时间。只有记录 `COMMENT` capability 才提供发表框，只有评论 `canDelete` 才提供携带 version 的确认删除；路径、当前成员或流程状态均不用于推断资格。除这些受限 capability、管理完整基线、选择/任务 code-name、可写字段、临时上传状态、失败结果约束和 mutation version 外，不显示或缓存审批实例、进度、现有附件、时间或备注。

目录项可进入 `/workflows/:workflowId` 查看同一服务端授权的只读定义详情。详情只呈现流程名称、业务对象、成功/失败结果名称、阶段名称/顺序/概率、必填字段码、任务名称与必填标记，以及是否含审批门；阶段码、任务码、审批定义 ID、状态、适用范围、资源级 capability 与时间信息不显示、不缓存。详情路径 ID 不是授权依据，响应 ID 不匹配或基线字段不完整时页面失败关闭。

每个新页面首次实施前，在对应 feature 的 `README.md` 记录具体 H5 文件、借鉴交互、明确不继承的旧行为和新 API 差异。

单条“新建回款计划”以当前已发布 API 的字段为准更新如下：在合同、到期日和计划金额后，可选择填写非负整数的“提前几天提醒”，并可填写“备注”，再选择收款方式；未填写的可选提醒和空白备注均不发送。批量计划的每条行也可填写非负整数提醒和备注。两种流程的提醒和备注只存在当前表单与本次认证请求，既不进入 URL、缓存或持久化存储，也不作为详情编辑基线。

单条“新建回款计划”还在 `fields:read` 下按当前身份的 ACTIVE 非内置 RECEIVABLE_PLAN 目录渲染动态字段：USER/DEPARTMENT 只由 `organization:read` 的受限目录选择，FILE 仅绑定 `files:write` 下同一草稿已确认 `UPLOADED` 的服务端 ID。批量创建同样逐行渲染和提交标量字段，但生成契约不含文件草稿，仍不提供附件；任一必填 FILE 或 RELATION 都不会降级为自由文本或 ID，而是关闭批量创建。

## 合同与发票列表动态字段

回款与发票全局列表在桌面端提供服务端授权的当前页勾选。回款显示“转移 / 删除”；发票显示“转移 / 重置开票信息 / 删除”。转移只在 `organization:read` 下从服务端成员目录选择，不能输入 ID；删除、重置均有二次确认。发票选择包含非已开票项时重置按钮禁用，包含非待开票项时删除按钮禁用并说明原因。成功、失败、加载和已选数都由实际批量请求驱动；移动端不伪造跨卡片选择，切换列表查询或身份不保留旧选择。

合同全局列表在桌面端、且当前授权分别具备 `contracts:assign + organization:read`、`contracts:export` 或 `contracts:delete` 时提供勾选后的“转移”“导出选中”“添加团队成员”“移除团队成员”和“删除”。成员弹层标题分别为“添加团队成员”“移除团队成员”。“导出选中”只从当前服务端行收集 ID/version，通过认证 Blob 下载；执行中显示加载并禁用重复点击，成功提示数量但保留选择，服务端拒绝时展示审阅后的中文错误。所有成员弹层只展示服务端返回的在职成员，用户不能输入成员 ID；添加以可搜索的“点击选择（多选）”下拉选择成员，明确选择只读/读写以及“有效时间”的不限或截止到日期，保存按钮在必填项完成前禁用；移除有二次确认且不允许移除负责人；删除有二次确认并说明任一关联发票、回款或计划会使整批不删除。已选数、成功提示和错误提示均对应实际请求；查询、分页、筛选或身份变更不保留旧勾选，移动端不伪造批量控制。

合同与发票全局列表在 `fields:read` 可用时显示服务器目录中的活动非 FILE 自定义列。列标题、选项和格式来自目录，值只取自同一列表响应中的已过滤、脱敏 `customFields`；缺少目录、字段停用或响应未回显值时保持空白。排序控件提供固定排序和目录确认的 `custom:<fieldCode>:asc|desc`，不会在浏览器重排已返回页面，也不会将金额、产品、税务或开票资料加入动态列。发票详情也会在相同权限下按需读取 INVOICE 目录，并只把同一详情响应已回显的 ACTIVE、非内置、非 FILE 自定义值作为只读描述展示；这些值不参与编辑、权限或范围判断。

## 线索与联系人列表批量操作

参考站线索列表已确认当前页勾选入口；本地线索和联系人在桌面表格沿用同一选择反馈，已选择时显示服务端权限允许的“转移”和“删除”。转移弹层按姓名检索受限成员目录，不能输入成员 ID；删除说明任一旧 version、不可见记录或活动下级都会使整批保持不变。移动卡片不模拟跨卡片批量勾选，成功与冲突提示只来自真实 API 响应。

商机列表复用同一桌面当前页选择方式，并展示实际的批量转移/删除反馈；移动卡片仍不伪造跨卡片勾选。所有成员候选、版本冲突和删除结果均以服务端响应为准。

## 线索、联系人与产品 CSV 导入

线索、联系人和产品列表在同时拥有相应对象写入权限与 `files:write` 时显示“导入 CSV”。弹窗先提供服务端定义列的模板下载，再接受一个不超过 1 MB 的 CSV；上传不会直接创建业务记录，而是写入服务端私有草稿并等待安全检查。检查完成后只显示可导入行数，以及问题的行号和已审阅中文原因，不显示原始单元格、文件内容或服务端原始错误。存在任一问题时“确认导入”不可用，并可下载服务端按同一活动草稿重新生成的错误报告；报告经认证 Blob 立即保存，固定为 `rowNumber,errCode`，不保留、解析或展示其内容。全部通过时，确认动作以草稿原始 version 请求服务端处理。线索和联系人在同一事务内全量创建；产品模板固定 `name,code,categoryId,unit,listPrice,description,availability`，服务端按产品编码跳过已存在记录和同一文件重复记录，绝不覆盖旧产品。弹窗的“查看导入记录”打开独立、可关闭的完成记录页，加载、空态和错误均有具名反馈；页面严格只显示当前成员、当前对象近七天的完成时间和导入计数，不暴露源文件、CSV 内容、失败行或其他成员身份。完成页只显示服务端计数并刷新当前列表；取消会撤回草稿和源文件，上传、确认、错误报告下载或撤回进行中不可关闭窗口。
