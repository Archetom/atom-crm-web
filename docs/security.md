- 审批待办入口和查询都要求 `approvals:read`，且用户主动打开弹层后才请求固定 `PENDING` 桶；前端不允许从 UI 输入 bucket、状态、业务类型、主体、关键字或全量范围，也不轮询未审数量。列表响应在写入 Query 缓存前只解码正审批 ID、`PENDING` 状态、可选非空标题、非负 version 与受限 `allowedActions`；审批事实、业务对象/关联、申请人、参与者和时间戳立即丢弃。批量通过/驳回只允许所选每一条都具有对应服务端 capability，提交各自 version；响应必须 `atomic=true`、覆盖全部请求项，并且只有 `applied=true` 时才失效待办缓存。失败批次只展示服务端的受限状态与稳定错误码，绝不局部更新或自动重试。用户选择列表项后，详情查询仍需同一读取权限并要求服务端返回相同 ID；其缓存仅保留受限实例状态、步骤名称/顺序/状态与可选处理时间，以及服务端下发的非负 version 和受限 `allowedActions`。详情操作只在该 capability 出现时展示，提交同一 version；转审候选只从当前实例的专用分页接口读取，服务端仍在写入时重新复核成员状态、当前任务、记录可见性和并发。动作成功必须回显同 ID 的安全投影，前端随即失效待办缓存；409 不自动重试。浏览器不比较当前身份、申请人或任务受理人 ID，任务 key、受理人、备注、模式、事实、附件和实例生命周期均不展示或缓存。
- 客户、线索、联系人、产品、商机、合同、发票、回款、回款计划和回访详情的“发起审批”仅在服务端 authorization 明确含 `approvals:submit` 时显示；每个页面只传递其固定业务对象类型和当前详情已确认的正 ID，用户明确打开后才读取服务器据此裁决的起始定义。每个审批人选择只请求同一对象、定义和选择 code 绑定的候选分页。浏览器只在所有服务端选择项已显式填写、同一选择组合刚刚预览为 `executable=true` 时提交 `definitionId`、对象 ID、选择成员和一次随机 UUID 幂等键；不提交业务 facts、路由条件或任意成员目录结果。选择变化会使预览和幂等键失效，网络失败的同一提交保留同一键，且不自动重试。服务端仍在预览和提交时复核当前成员、记录可见性、字段权限、候选资格、路由、幂等性和并发。成功会失效当前对象起始选项、审批待办、当前详情与同一身份的业务列表。回款与回访只在这些已可见业务记录上保存服务端回显的受限 `approvalStatus` 枚举；未知值丢弃、空值仅表示“未发起”，不能据此推断任务归属、申请资格、审批权限或业务生命周期。业务列表不提供根据状态生成的批量操作；批量审批仍只使用审批待办逐实例回显的 capability 与 version。
- 部门成员工作台要求 `organization:read`；路径中的部门 ID 先与当前服务端目录精确匹配，才允许请求成员分页。`includeDescendants=true` 仅是查询意图，不从浏览器部门树、缓存、当前身份或 URL 推导成员集合；服务端重新验证选中可见部门，并只把其在职后代加入同一租户范围。前端只保留安全成员投影和分页事实，取消部门筛选会清除该范围参数；部门由服务端成员资格投影，登录名和角色分别由服务器在 `users:read`、`roles:read` 下裁决，岗位、性别和直属上级不下发也不显示。
- 审批定义目录入口和查询都要求 `approvals:manage`，且仅在用户主动打开头部弹层后分页请求。浏览器固定只发送页码和每页数量，不提供对象类型、状态或关键字的本地过滤，更不会根据其他审批数据或本地身份推导管理范围。响应在写入 Query 缓存前只解码正定义 ID、非空名称、受限对象类型和受限状态；描述、重复规则、发起人/管理者/部门成员范围、步骤、条件、版本及时间立即丢弃。服务端继续复核活跃成员和定义管理权限；前端不提供创建、编辑、预览或状态切换。
- 审批定义最小草稿创建同时要求 `approvals:manage` 与 `organization:read`；两个成员多选都只使用服务端返回的在职可见成员目录，浏览器不从当前身份、定义列表或任何缓存猜测候选。表单只提交用户明确选择的审批成员和兜底管理员、名称、业务对象与任一/全员方式，并固定生成初始停用的 `ONCE` 单 `MEMBER` 步骤及 `MANAGERS` 兜底；不提交描述、发起人范围、部门、角色、条件或 version。服务端继续复核成员在职性、定义管理权限、对象、路由与引用约束；成功响应重新收敛为目录投影并失效定义列表，后续启用、编辑与路由扩展不能由本地状态推导。
- 审批定义状态操作只要求 `approvals:manage`，但在用户选择目录项后必须重新读取独立身份隔离的窄基线；基线只接受同一路径正 ID、受限状态和非负 version，路由、成员、条件、描述、重复规则和时间立即丢弃。浏览器经明确确认后仅发送目标 `ACTIVE`、`INACTIVE` 或 `DELETED` 与该 baseline version；成功响应必须回显同一 ID 与目标状态，随后只更新该窄基线并失效目录。服务端继续复核 active membership、定义引用、激活约束和乐观锁，409 不自动重试。
- 审批定义最小模板编辑同时要求 `approvals:manage + organization:read`。打开编辑器时重新读取独立身份隔离的完整定义，但只接受初始停用、`ONCE`、无发起范围/部门/条件/角色、固定 `step-1` 且单 `MEMBER` 步骤/管理员兜底的精确基线；否则失败关闭。仅这些基线的成员 ID、名称、对象类型、任一/全员方式与 version 才能短暂进入表单，成员候选仍只来自服务端在职可见目录。保存以原 baseline version 发送完整最小模板；服务端继续复核成员、引用和并发，成功响应重新解码为同一最小基线并失效目录。

- 联系人与商机全局列表的 `customerId` 只会在 `customers:read` 已授权、URL 值为精确正安全整数且同一受限客户详情确认当前可见后发送。候选只来自同一身份的客户目录，解码边界仅保留 ID/名称；联系人/商机、负责人、金额、管线、阶段、协作者、动态字段和附件不从候选或 URL 读取、推断或缓存。确认未完成、无权或详情不匹配时查询保持关闭；联系人 CSV 导出只继承该已确认范围，服务端继续复核客户可见性、字段访问和业务对象数据范围。
- 合同全局列表的 `opportunityId` 只会在 `contracts:read + opportunities:read` 已授权、URL 值为精确正安全整数且同一受限商机详情确认当前可见后发送。候选只来自同一身份的商机目录，解码边界仅保留 ID/名称；客户、负责人、管线、阶段、金额、联系人、产品、动态字段和附件不读取或缓存。它可与客户筛选共存，任一确认未完成、无权或详情不匹配时查询保持关闭；服务端继续复核商机可见性、合同数据范围与 `OPPORTUNITY` 字段访问。

商机基础编辑只在 `opportunities:read + opportunities:write` 下取得 identity 隔离的安全编辑基线。仅当服务端确认全部完整替换字段未遮罩、可读且可写时，`editable: true` 才可携带名称、客户、管线、阶段、预计成交日期、预计金额、下次联系时间和说明；`editable: false` 含任何业务字段即失败关闭。该基线只用于当前编辑表单和同身份查询键，不共享给列表或普通详情。PUT 仅由该基线和用户明确输入构造，始终携带原始 version；普通详情、列表、客户/管线目录或本地默认值不得补齐。改客户只有从 `customers:read` 受限目录明确选中的候选才会替换基线 ID；改管线和阶段只有从 `opportunity-pipelines:read` 的同一活动管线目录成对确认后才会替换基线 code。目录无法确认时只原样保留现有基线，不发送半个关系更新。清空下次联系时间明确发送 `null`，409 不自动重试。

# 权限与安全基线

应用头部“全局新建”是一个导航入口而非授权来源：每个候选同时由服务端返回的导航树和本地防御性 `*:write` 检查限制，点击后仍进入受路由与服务端保护的真实创建流程。浏览器不会因为存在创建路由、参考站显示某个入口或本地按钮状态而自行推断 actor、tenant、authority 或数据范围。

线索和联系人批量转移仅在分别具备 `leads:assign + organization:read` 或 `contacts:assign + organization:read` 时开放，候选成员只来自当前身份服务端目录，浏览器不接受或推断 actor ID。批量删除仅在对应 `*:delete` 下经确认执行。四个命令只提交当前页服务端投影的 ID/version；勾选、关键词和成员目录搜索只保留当前页面内存，不进入 URL、浏览器持久化存储、日志或跨身份缓存。409 不自动重试，服务端重新裁决每个目标的可见性、字段策略、成员资格、层级依赖与并发，并以原子结果决定是否刷新列表。

商机批量转移和删除遵循同一边界：只在 `opportunities:assign + organization:read` 或 `opportunities:delete` 下显示，成员 ID 只由受限服务端目录产生，提交只含当前 `opportunityId/version`。浏览器不从商机阶段、客户、负责人或本地身份推断作用域；409 不重试且失败不修改当前列表缓存。

合同批量团队成员只在 `contracts:assign + organization:read` 下显示。浏览器只从当前页安全行读取 `contractId/version`，候选只来自受限在职成员目录；添加请求明确给出 `READ|WRITE` 与用户选择的 null 或 `YYYY-MM-DD` `effectiveUntil`，移除经确认且不由浏览器判断该成员是否已在每份合同中。服务端对整个选择重新锁定并检查 owner scope、版本、活动成员、负责人排除、协作者容量和截至日；截至日经过后数据范围 SQL 不再将该成员作为协作者。错误或冲突时浏览器不部分修改缓存、不会自动重试 409，也不把成员、截至日或团队状态写入 URL 或持久化存储。

合同、回款、发票和回访的保存视图与临时高级筛选只在 `saved-views:read` 下启用，方案创建、编辑、默认和删除另需 `saved-views:write`。临时 `conditions` 只保存于当前 React 页面状态，不能进入 URL、sessionStorage、localStorage、日志或导出；请求只会在四个生成的 `POST /query` body 中发送 `conditions` 或 `savedViewId` 之一。后端重新验证保存视图归属和对象类型、字段活动/可筛选状态、读取与脱敏策略、操作符和值数量，并对客户、联系人、商机、合同及回款计划关系条件再次确认当前可见性和租户一致性；持久化条件最终仍与对象数据范围相交，页面不能借结果推断未授权关系或字段。

客户列表独立查重入口只在 `customers:read` 下可见。浏览器本地校验至少一个客户名称或 E.164 联系电话后，才向生成的 `POST /api/v1/customers/duplicate-check` 发送这两个可选字段；不发送当前 actor、tenant、业务线、列表项或任何客户详情。响应只接受布尔重复事实，不显示或缓存匹配客户、联系方式、负责人或其他字段；取消、关闭与失败均不会影响客户列表查询、URL 或缓存，服务端继续裁决当前成员的数据范围与字段访问。

联系人列表独立查重入口只在 `contacts:read` 下可见。浏览器本地校验至少一个联系人姓名或 E.164 联系电话后，才向生成的 `POST /api/v1/contacts/duplicate-check` 发送这两个可选字段；不发送当前 actor、tenant、业务线、列表项或任何联系人详情。响应只接受布尔重复事实，不显示或缓存匹配联系人、联系方式、负责人或其他字段；取消、关闭与失败均不会影响联系人列表查询、URL 或缓存，服务端继续裁决当前成员的数据范围与字段访问。

联系人“我关注”场景只恢复受限 URL 值 `scene=starred`，并向生成的联系人列表/CSV 导出请求发送 `starred=true`；它不发送 actor、成员、tenant 或范围 ID，也不在已加载联系人上二次过滤。服务端仍对当前成员的关注偏好、联系人数据范围与字段访问作最终裁决。

线索列表独立查重入口只在 `leads:read` 下可见。浏览器本地校验至少一个线索名称或 E.164 联系电话后，才向生成的 `POST /api/v1/leads/duplicate-check` 发送这两个可选字段；不发送当前 actor、tenant、业务线、列表项或任何线索详情。响应只接受布尔重复事实，不显示或缓存匹配线索、联系方式、负责人或其他字段；取消、关闭与失败均不会影响线索列表查询、URL 或缓存，服务端继续裁决当前成员的数据范围与字段访问。

线索、联系人、客户和商机列表的批量跟进入口同时要求对应对象读取及 `activities:read + activities:write`。勾选仅保存当前页的已服务端投影记录，并在分页、关键词、场景、排序、保存视图或临时筛选变化时清空，绝不进入 URL、浏览器持久化存储、日志或跨身份缓存。浏览器只从服务端 `METHOD` 目录选择方式，并为每条已选记录提交固定 object type、该投影 ID、方式、可选目的、内容和发生时间；不会发送或从本地推导 tenant、actor、authority、version、负责人、关系、附件、下次联系时间、模板或动态字段。客户端限制 1–100 条，`POST /api/v1/activities/batch` 失败和 409 均不自动重试；服务端逐条复核成员资格、写可见性、数据范围、同租户与方式目录，并原子决定结果。

线索、联系人和产品 CSV 导入只在分别具有 `leads:write + files:write`、`contacts:write + files:write` 或 `products:write + files:write` 时出现。浏览器只把用户明确选择的一个 `.csv` 文件交给固定 `import-draft` 目标的受控上传意图与认证原始内容端点；不把 tenant、actor、authority、草稿 ID、文件字节、文件名、上传状态、预览问题或原始错误写入 URL、日志、查询缓存或浏览器持久化存储。模板列与导入记录均以服务端响应为准，前端只映射行号和经审阅的 `errCode`；它不解析或显示原始单元格。确认只提交草稿 ID 与服务端 version，取消同样使用该 version；任何 409 均不自动重试。服务端仍重新裁决成员资格、对象写入范围、草稿创建者、附件扫描状态、CSV 约束、字段策略、关联可见性与事务结果；产品还以规范化产品编码去重，已有记录和同文件重复项均被跳过，浏览器不能请求覆盖。
CSV 导入记录只可经认证的 `GET /api/v1/crm-import-drafts/history/{objectType}` 读取。浏览器不把结果写入 URL、持久化存储或跨身份缓存；接口只按当前认证成员、对象类型和近七天已完成草稿返回完成时间与计数，不泄露源附件、原始 CSV、失败行、草稿版本或其他成员身份。预览有问题的活动草稿可经同一身份下载 `GET /api/v1/crm-import-drafts/{draftId}/error-report`；服务端重新验证成员、对象写入、`files:write`、草稿归属和附件状态，再以认证 Blob 返回固定文件名、`Cache-Control: no-store` 和 `X-Content-Type-Options: nosniff` 的 `rowNumber,errCode`，而非原始文件名、源字节或单元格。前端立即保存 Blob，不写入查询缓存或持久化存储。
