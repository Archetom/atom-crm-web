- 回款全局列表的回款计划筛选只在 `receivable-plans:read + customers:read` 下开放：候选仅保留服务端回显的 ID 与期数，刷新后再通过同一受限计划详情确认；`receivablePlanId` 未确认、无权或格式非法时不发送，可与客户和合同筛选同时使用。

- 合同、回款、发票和回访全局页与头部全局新建均先通过 `customers:read` 保护的受限目录选择当前可见客户；合同、回款和发票随即进入已有客户上下文真实表单，回访则提交最小 `ReturnVisitCreateRequest`。取消时仅恢复同一对象列表的 query，不接受外部返回路径。创建成功仍由各对象既有 mutation 精确失效查询，且只有可读取返回对象时才进入服务端回显的客户上下文详情。

- 客户上下文发票表单会提交用户明确填写的合同、正金额、申请日期、发票类型、个人或单位抬头与可选寄送/备注字段；单位抬头的纳税人识别号必填，开户行、账号、地址和电话只有选中单位时才允许填写与发送。仅 `invoices:assign + organization:read` 可从服务端成员目录选择负责人并提交其 ID，未选择时不补齐负责人。`fields:read` 下会按当前身份的 ACTIVE 非内置 INVOICE 目录提交标量 `customFields`；USER/DEPARTMENT 仅取 `organization:read` 下受限目录 ID，FILE 只绑定 `files:write` 下同一 INVOICE 草稿中已确认 `UPLOADED` 的文件 ID。必填值不能安全完成时关闭创建，RELATION 不会降级为自由文本或 ID。浏览器不计算金额，也不会采集审批人/流程。
- 客户上下文回款表单会提交用户明确填写的合同、可选服务端可用计划、到账日、正金额、收款方式与可选备注；备注留空会被省略，且只留在当前表单与本次认证请求中。仅 `receivables:assign + organization:read` 可从服务端成员目录选择负责人并提交其 ID，未选择时不补齐负责人。`fields:read` 下会按当前身份的 ACTIVE 非内置 RECEIVABLE 目录提交标量 `customFields`；USER/DEPARTMENT 仅取 `organization:read` 下受限目录 ID，FILE 只绑定 `files:write` 下同一 RECEIVABLE 草稿中已确认 `UPLOADED` 的文件 ID。必填值不能安全完成时关闭创建，RELATION 不会降级为自由文本或 ID。浏览器不计算金额，也不会采集审批人/流程。
- 回访详情在完整可见基础字段、对应关系状态和所需读取权限均满足时，可选择、更换或经二次确认清除联系人/合同关系；清除仅发送刷新后生成契约允许的一个关系字段 `null` 与服务端 version，另一个关系刻意省略保留。
- 市场活动 API 已在隔离 MySQL 上运行完整迁移并通过真实 HTTP CRUD、负值拒绝、版本冲突、软删除及 OpenAPI 合约断言；浏览数和提交数以非负、版本化持久字段读写，员工和部门参与者使用独立关联表并只接受当前租户的活动成员/部门。活动可关联同租户、未删除且目标与关联对象一致的既有 `LEAD`/`CUSTOMER` 营销表单；只有表单处于 ACTIVE 时响应才回显完整 `marketingFormPublicId`，前端据此生成公开链接，绝不拼接或猜测公开标识。创建客户或线索活动时可在同一请求嵌入生成类型 `marketingForm`：服务端只在调用者同时具备活动写入和表单写入权限时，以同一事务创建未启用的目标匹配采集表单并关联，既有 ID 与内嵌请求互斥，更新拒绝内嵌表单；联系人不会被浏览器映射为此路径。前端从同一实例的生成快照读取表单目标、目标字段目录和提交记录目标 ID，列表查询只发送声明的关键词、关联对象和分页，参与人员不会在浏览器展开部门或手输 ID。

## 2026-08-11：线索、联系人与产品 CSV 导入

参考站的线索、联系人和产品列表导入现对齐为“下载服务端模板 → 选择 CSV → 受控上传与安全检查 → 仅行号/错误码预览 → 确认”的真实闭环。入口同时要求对象写入和 `files:write`；原始文件只在一个私有 `import-draft` 附件目标中短暂存在，不能从 URL、查询缓存、持久化存储或页面错误中读取。模板列、最大 1 MB/200 行限制、UTF-8/表头/字段校验、当前租户与写入范围均由服务端最终裁决；预览含任一问题时确认关闭。确认会在单个事务中创建全部线索或联系人并撤回源文件；产品导入则由服务器以编码去重，跳过已有编码和同文件重复编码、保留既有产品不被覆盖，再撤回源文件。取消同样版本化撤回草稿；成功只显示服务端计数并精确刷新同一身份列表。产品 CSV 导出已补齐为当前列表筛选的受控 Blob 下载，当前成员的导入历史也在同一弹窗中可查。

2026-08-11 更新：参考站导入弹窗的历史入口现由 `GET /api/v1/crm-import-drafts/history/{objectType}` 对齐为可关闭的当前成员记录表。它只读取同对象、近七天的完成时间和导入条数，并提供加载、空态、失败和分页状态；源文件、CSV 内容、失败行、草稿版本与其他成员均不暴露。预览发现错误时，当前活动草稿提供 `GET /api/v1/crm-import-drafts/{draftId}/error-report` 的认证 Blob 下载：服务端重新解析同一私有附件，只生成 UTF-8 `rowNumber,errCode`，固定文件名并禁止缓存；浏览器不保存或解析报告内容。未确认草稿及其私有源附件同样采用固定七天保留：到期 worker 将草稿标记为 `EXPIRED`、撤回关联并进入既有精确字节回收流程；前端只接收真实的失效结果，不以静态按钮伪造清理。

2026-08-11 更新：产品列表现已提供 `products:export` 守卫的 CSV 导出确认态。固定字段为名称、编码、单位和可用性；浏览器只把当前关键词、已确认分类、可用性、静态或经字段目录确认的自定义排序、保存视图或内存临时条件提交给生成契约，服务端再次裁决读取/导出权限、字段未遮罩策略、筛选、5,000 行与 16 MiB 边界。下载通过认证 fetch 转 Blob，CSV 内容不进入页面、缓存或存储。
